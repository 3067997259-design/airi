# 远距伴飞：预算门控、协同减速与走廊接线

日期：2026-09-16。状态：设计，尚未实施。

依赖：[能力深化总方案](./capability-deepening-plan.md) 的 CD-0、CD-L、CD-E、CD-F；[鞘翅三维导航](./elytra-navigation-design.md)；[空中跟随与地空切换](./air-follow-design.md)。模式参考：弹道的移动目标预判（`ballistics/intercept.ts` 的到达时间求解思路）。

上游证据：本轮真机冒烟（[evidence/live-acceptance-20260916](./evidence/live-acceptance-20260916/) 与 [MODS](./MODS.md) 2026-09-16 条目）。

## 1. 现状与问题

- 64 格是**精细观测半径**，不是杀死条件：玩家目标在 64 格外可用玩家列表粗定位（F-02 已修复），跨边界跟随后台可维持。
- 真机证据：一次 108 秒跟飞消耗 114 发烟花（约 1 发/秒）。原因在 live 驱动 `movement/air-track.ts`：爬升、水平速度低于 `THRUST_SPEED`、或距离超过间距带，任一条件成立就每个策略拍点火。距离被拉大时近似连续点火。目标是靠燃烧堆闭合，不是靠能量管理。
- 同一批冒烟暴露的其他缺口：高速下撞山阵亡（无避障走廊）、硬着陆剩 2 血、水上平台落水、进近在 8 格处悬停约 30 秒后 `safety-landing`。
- 新 `flight/` 模块（CD-E1/E2）与新走廊已离线完备但**未接 live 驾驶**：`simulateFlight`（逐 tick 物理与轨迹记录）、`planCorridor`（4 格粗自由空间与入口）、`planRollout`（候选动作与姿态盒扫掠）、`selectLaunchPoint`、落点评估、复飞与应急。当前只接入共享 `LandingSite` 与 `classifyTouchdown` 契约。
- 目标：把"追不上"变成**可判断、可商量、可终止**的事情；同时把上述实验模块接进 live 驾驶。

## 2. 设计决定

### D1 语义：`auto` 内的伴飞策略，不新增模型工具

- `game_follow` 的 `travelMode: 'auto'` 内部增加伴飞策略。新增可选参数 `escort: 'off' | 'suggest' | 'on'`，默认 `off`，保持现有语义不变。
- 不新增模型工具；模型仍然只看到 `game_follow`。伴飞是执行器的策略，不是新的工具面。
- 状态机位置：在 `air-follow` 的 `ground-follow` 与 `assess-launch` 之间增加条件状态 `escort`。`escort` 只决定"是否值得起飞、是否发建议、闭合是否在改善"，起飞与驾驶仍走既有 `launching`/`air-track`/`approach-landing` 路径。

### D2 可行性门（乐观启发）

- 输入：同维度目标观测（固定 UUID、位置、速度、年龄、误差）、自身状态、烟花余量、备用落点储备、版本化物理档案；接线后加入走廊的绕行系数。
- 估算：允许尝试的条件是**乐观需求**在预算内——按"目标保持当前速度、全程允许点火上限、地形绕行乘系数"估算追上所需烟花。乐观都超预算时不点火。
- 判据：`fireworks - reserve >= 乐观需求 × (1 + 安全余量)` 才进入 `escort`；否则返回类型化 `cannot_catch_up`，不点火、不搭塔，地面策略照旧。
- 乐观值是"允许尝试"的门槛，不是承诺；真实闭合由 D4 的窗口评估决定。

### D3 协同协议（建议减速）

- `escort: 'suggest'` 只发建议：保持当前 XZ 方向、收油或降速；消息包含当前航向与期望。
- 通道用 `game_say`（或 AIRI 聊天）；频率上限（建议 2 条/分钟）、内容变化即失效、命令结束不追加。
- **用户配合只作为收敛加成，不作为门控前提**：D2 与 D4 按"目标不配合"计算；配合只改善结果，不改变承诺。

### D4 追逐控制与能量管理

- 能量优先：爬升换势能、滑翔换距离；推力只在三种情况下施加：高度低于所需、速度低于滑翔下限、闭合速率为负且预算允许。
- 闭合窗口：每 5 秒评估相对距离趋势；连续 2 个窗口闭合速率 ≤ 0 时判 `escort_inconclusive`，转安全降落。不无限追。
- 高度政策：接线前保持地形以上安全余量；接线后由走廊提供低空路线。
- 评估节拍与观测新鲜度绑定：粗定位 1 Hz 时缩短预测窗口并扩大误差余量，不做分钟级承诺。

### D5 结果与诚实终止

新增终态：`cannot_catch_up`、`escort_inconclusive`、`escort_completed`。回执新增：闭合速率序列、每公里烟花、剩余储备、最后一次目标观测年龄、是否发送过建议与发送次数。

### D6 接线范围（顺带纳入未接线的实验性改动）

- 决策层接线：`planRollout` 的候选动作替换 `air-track` 的"朝目标打舵 + 阈值点火"；`simulateFlight` 提供预测；`planCorridor` 提供绕障路线。
- 策略流：先维持轮询（主进程 2–5 Hz），回执标注"按轮询"；独立 IPC 通道后补。
- 标定：保留版本化档案与逐 tick 轨迹记录（`trajectoryToJsonl`）。校准前 `escort` 默认关闭；校准不通过的档案不启用其自动求解，也不启用低空捷径。

### D7 观测与不确定性

- 目标观测只用固定 UUID、维度核对、年龄与误差预算；超出新鲜度窗口时降低控制强度并扩大余量。
- 不做跨维度追逐；传送、换维度、目标离线即终止本段。

### D8 明确不做

- 不新增模型工具；不自动搭塔或搭桥追空；不无限追逐；校准前不做低空捷径；没有可用备用落点不起飞；不把乐观估算写成"会追上"的承诺。

## 4. 需主流程采集（验收场景）

- 初始间隔 200 格与 500 格；目标保持航向匀速、目标收油降速、目标变向、目标加速逃离。
- 地形：越山、低顶棚、狭谷；资源：烟花不足、备用落点不足。
- 每类至少 5 次；记录闭合速率曲线、烟花消耗、终止原因、是否发送建议与用户是否配合。
- 失败样本与成功样本同样保存；成功率附全部尝试数。

## 5. 风险与回退

- 不收敛：窗口评估加诚实终止，不承诺追上。
- 走廊未知区域：标记不可用，不当作自由空域；接线后仍按"未知不是空气"处理。
- 标定失败：停用该档案自动求解，降级为"只发建议 + 常规跟随"。
- 性能：决策只在主进程策略拍运行，不在客户端 tick 内做搜索。
- 回归：LR-0 保持默认行为不变；开关未开启时与现状一致。

## 6. 与验收清单的关系

- 本专题是清单 B 类之后的新增专题；LR-0 与清单的 B0 接线批是同一批工作。
- `L-02`/`L-06` 的观测问题已由 F-02 修复解决；伴飞不改变 64 格精细观测语义，只改变飞行经济学与决策。
- CD-E 的正式验收（E-01 至 E-10）在 LR-0 之后进行；LR-4 的残差标定与 E1 的 10/20/40 tick 校准共用同一份档案与轨迹记录。
