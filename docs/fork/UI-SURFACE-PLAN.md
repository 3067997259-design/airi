# UI-SURFACE-PLAN：聊天、舞台与设置窗口的表面与反馈契约

日期：2026-09-11。状态：UI-0/UI-1 由 FIX-LIST 批次先行落地；UI-1 剩余部分、UI-2、UI-3、UI-4
于 2026-09-11 实施，真机复验待用户重建。实施记录见 [§十二](#十二实施记录2026-09-11)，
验证明细见 [UI-SURFACE-20260911](./evidence/short-scenarios/ACC-20260907-01/UI-SURFACE-20260911.md)。
定位：把 [插件与 Minecraft 勘探](./extension-and-minecraft-exploration.md) 里的「已确认的 UI 方向」独立成篇。
那篇文档把 UI 与两个宏大方向（自开发插件、Minecraft 接入）并列，而 EP/MC 两侧已各有
[执行计划](./extension-execution-plan.md) 与 [接入计划](./minecraft-execution-plan.md)，UI 一侧一直缺一份同等细致的文档。
本文件补齐这一侧，并把它与实际验收中观察到的 UI 缺陷绑定。

上游关系：[DESIGN-PRINCIPLES](./DESIGN-PRINCIPLES.md) 的结构优先、可审阅性；
[TASK-RUN-AND-UI-PLAN](./TASK-RUN-AND-UI-PLAN.md) 的 `TaskRun` 投影与三种界面投影是本文的**数据前提**，本文不重设计它。

## 一、结论

UI 侧的缺口不是「缺一个好看的界面」，而是**缺一份可检验的表面与反馈契约**。实测暴露的问题有同一个形状：

> 界面允许用户做一个动作，动作却没有结果、没有原因，也不留痕迹。

因此本文把 UI 工作定义成三件事，按顺序：

1. **反馈契约**：每个用户动作在有限时间内必须有可见结果或可见拒绝理由；静默是缺陷，不是省事。
2. **表面预算**：一个窗口只有一个主输入位；辅助表面（侧通道、问题卡、计划卡）有高度上限与折叠规则，
   不能把正文与输入框挤出视口。
3. **归属与来源**：聊天正文只展示当前会话的任务与计划；跨会话内容走全局入口；未归属内容进未归属区，
   不伪造来源会话，也不因「完成」而删除证据。

三件事都不依赖新功能，全部可以在现有组件上收敛。

---

## 二、范围与非目标

**范围**：桌面 `stage-tamagotchi` 的四类窗口——主窗（舞台，leader）、聊天窗、设置窗（follower）、
其它工具窗（BeatSync / widgets / notice / onboarding）——的表面布局、反馈、窗口角色与可测试钩子。

**非目标**：

- 不重设计 `TaskRun` 投影与计划车道（属 TASK-RUN-AND-UI-PLAN）。
- 不改上游的品牌、主题与视觉系统；不引入新的样式方案（仍用 UnoCSS 与 `packages/ui` 原语）。
- 不做移动端与 Web 端的适配设计；先把 Electron 本机路径收干净。
- 不改语音/转写链路的官方来源（属上游）。
- 不为「更好看」而重排信息层级；本文所有条目都能对应到一条实测证据或一条不变量。

## 三、现状基线

### 3.1 窗口与角色

| 窗口 | 角色 | 渲染运行时 | 备注 |
| --- | --- | --- | --- |
| 主窗 `#/` | **leader** | 完整 | 持有舞台与 Live2D；journal 投影的发布者 |
| 聊天窗 `#/chat` | follower | `stage-runtime=minimal` | 主输入位；**装不了设置页**（实测 `body.innerText` 长度为 0） |
| 设置窗 `#/settings` | follower | 完整 | 设置页只在完整运行时可用 |
| BeatSync / widgets / notice / onboarding | follower | 各自页面 | onboarding 承载首屏与恢复说明 |

窗口选择是**每窗口**的：`chat-session` 的 `activeSessionId` 不跨窗同步（源码注释明确「属于一个窗口」），
所以「主窗在看哪个会话」与「聊天窗在看哪个会话」是两件事。

### 3.2 表面组件

| 组件 | 责任 | 现状问题 |
| --- | --- | --- |
| `InteractiveArea.vue` | 主输入位、附件、计划卡、心流指示器、btw 卡、问题卡 | 一个文件里有 6 个表面，没有高度预算 |
| `history.vue` | 当前会话时间线 | 与上方表面争视口 |
| `plan-lanes.vue` / 计划卡 | 会话计划与长期目标 | 卡片可见性依赖会话与车道，缺全局视图 |
| `sessions-drawer/dialog.vue` | 会话列表 | 只有相对时间与预览，**无检索** |
| 技能页 / 记忆体页 / 生命模式状态卡 | 设置侧操作面 | 存在静默空操作（见四） |

### 3.3 数据来源

leader 发布 journal 的当前投影；窗口只读。任务与计划的**真值**在 journal 与 plans store，
UI 不得再维护一份。窗口局部状态（展开、筛选、滚动位置）不进同步。
`pinia-plugin-synced` 是**快照复制 + leader 路由**，不是共享 ref——这决定了「哪个窗口能做什么」。

### 3.4 一条已实测的跨窗口耦合

把主窗导航到 `#/chat` 后，聊天里的 `expression_set` 立刻失败：
`{"success":false,"error":"No Live2D model is currently loaded."}`。
即**舞台工具只在显示着模型的窗口里可用**，而这个依赖在 UI 上没有任何声明。
这是本文件要解决的第三类问题的样本（窗口角色未声明）。

## 五、设计不变量

实施后应能逐条检查；每条都能写成回归。

1. **单一主输入位**：任一窗口最多只有一个接受回车发送的输入元素；主输入位有稳定
   `data-testid="chat-composer"`（临时：占位符「说点什么...」）。
2. **反馈时限**：用户动作在 300 ms 内必须产生状态变化或可见反馈；「无反应」按缺陷处理。
3. **拒绝必须可解释**：任何不可用状态给出「原因 + 恢复入口」，三者至少覆盖：未登录、provider 未配置、
   技能/工作区不匹配。
4. **表面预算**：输入框上方的辅助表面（侧通道 + 问题卡 + 计划卡）合计不超过聊天区可视高度的
   40%；超出部分各自滚动或折叠，正文与输入位始终在视口内。
5. **归属不伪造**：聊天正文只展示当前会话的活动任务与计划；其它会话的长期目标走全局入口；
   无 `sessionId` 的计划与 attention task 进未归属区。
6. **证据不删除**：完成/取消只改变显示位置；`completed` 但仍有 `unverified` 步骤的计划不得当作成功归档。
7. **局部状态本地化**：展开、筛选、滚动、选中项属于窗口局部 UI，不进 Pinia 同步，不改调度所有权。
8. **窗口角色显式**：每个窗口声明它提供的能力（舞台 / 输入位 / 设置 / 工具页）；能力缺失时工具面据实裁剪并说明。
9. **首屏说真话**：恢复、未登录、无会话、无 provider 四种状态各有明确文案与入口，不允许退化成
   「全新安装」或「看起来正常但点了没用」。

## 六、反馈契约

按动作类型规定最低反馈，避免每次实现各写一套。

| 动作类型 | 最低反馈 | 现状参照 |
| --- | --- | --- |
| 即时成功（保存、切换、提交） | 状态行或 toast，含结果对象名 | 数据页状态行「导出。」「恢复的 profile 已启用。」 |
| 异步长动作（导出、恢复、迁移） | 进行中状态 + 完成/失败结果；失败给原因 | 数据页状态行；embedding 迁移在设置页显示错误文本 |
| **前置条件未满足** | 禁用 + 说明缺什么 + 去哪里补 | 目前多数是静默空操作（UI-C） |
| 无权限 / 未登录 | 明确文案 + 登录入口（沿用 R03 的恢复说明样式） | 新首屏已具备，聊天窗缺失（UI-D） |
| 排队/延后（Flow 忙碌、单槽占用） | 卡片等待原因 + 可见的排队位置 | 长期目标卡已有 `waitReason` |
| **策略性静默**（社交考量决定不说话） | 不面向用户弹提示；写 journal 决策 | 生命模式 `life/decision` |

最后一行的意思是：**只有产品刻意保持的静默才允许静默，且必须在 journal 留痕**；
其余「什么都没发生」一律按缺陷处理。

> 状态：已实施（2026-09-11）：`capabilities.stage` 声明与表情工具的可解释拒绝落地；
> 按能力在 leader 侧裁剪工具注册表未做（拒绝信息已满足本批通过条件）。

- **范围**：为每类窗口声明能力（舞台/输入位/设置/工具页）；工具面按窗口能力裁剪；窗口切换后
  给出「本窗口没有舞台，表情类工具不可用」这类**可见说明**而不是静默失败（UI-H）。
- **通过条件**：不变量 8；把主窗切到 `#/chat` 后调用 `expression_set`，得到可解释的拒绝而不是
  `No Live2D model is currently loaded.` 裸错误。

### UI-4　首屏与不可用状态的统一

> 状态：恢复说明与未登录态已在 R03 落地；无会话/无 provider 的禁用输入位与恢复入口于
> 2026-09-11 落地。工作区不匹配继续由 long 目标卡的等待原因呈现。

- **范围**：恢复未登录（UI-D 的文案部分）、无会话、无 provider、工作区不匹配四类状态的文案与入口统一；
  沿用 R03 已实现的「数据已恢复 / 请登录 `<owner>`」样式。
- **通过条件**：不变量 9；四类状态各有一条浏览器回归。

## 八、组件边界与数据来源

- **InteractiveArea**：按当前窗口选择会话；只管输入与本地表面状态；不改任务真值。
- **ChatHistory**：会话时间线；只读 journal 投影。
- **任务面板**（新增，UI-2）：跨会话浏览与归档筛选，复用现有卡片与来源导航。
  **不得**让各处各自维护另一份任务状态。
- **设置页**：只在完整运行时可用；聊天窗（minimal）继续不承载设置页，改为提供「在设置窗打开」的跳转，
  避免再次出现「点了没反应」。

## 九、i18n、可测试性与自动化钩子

- i18n 只改英文源与中文（Crowdin 规则）；新增文案统一放 `packages/i18n`。
- 关键交互元素加稳定 `data-testid`：`chat-composer`、`btw-composer`、`plan-card-*`、`run-now`、
  `skills-approve` 等；验收脚本据此定位，避免依赖占位符文本或 DOM 顺序。
- 每条不变量配一条可跑的回归；浏览器模式用例优先（本仓已有 `*.browser.test.ts` 与 Playwright 支持）。
- 视觉证据沿用既有 `docs/fork/evidence/` 目录与 vishot 流程。

## 十一、风险与不做的

- **风险：反馈泛滥**。每个动作都弹 toast 会淹没正文。缓解：按第六节分级，状态行优先，
  toast 只用于「看不见的状态行之外的动作」。
- **风险：表面预算做成硬编码高度**。缓解：预算按可视高度的百分比，随窗口尺寸变化；折叠状态是窗口局部状态。
- **风险：把窗口角色做成又一层同步状态**。缓解：窗口角色由启动上下文决定（`synced-leader` 与运行时参数），
  不新增可写状态；只在工具面裁剪与文案上体现。
- **不做**：跨设备/移动端布局、主题重做、动画重做、把设置页塞进 minimal 运行时、为 UI 引入新的状态库。

## 十二、实施记录（2026-09-11）

触发缺陷：聊天窗里已完成/已取消的长期目标卡跨会话堆积，正文与输入框被挤出视口。
落点如下，明细与验证命令见
[UI-SURFACE-20260911](./evidence/short-scenarios/ACC-20260907-01/UI-SURFACE-20260911.md)。

- **分类契约**：`planSurfaceLane(plan, sessionId)` 与 `planSurfaceLanes(plans, sessionId)`
  （`packages/stage-ui/src/stores/plans.ts`）返回 `current` / `other-session` /
  `unattributed` / `archived`。完成、失败、取消的计划归 `archived`；完成但未验证的计划保留
  琥珀色标记，并由计划中心 `待验证 N` 计数（不变量 6）。同一会话的会话车道只有一个
  standing 计划，被更新计划取代的旧计划归 `archived`。
- **时间线**：`InteractiveArea` 只把 `current` 与 `unattributed` 传给 `ChatHistory`；
  `plan-lanes.vue` 为未归属计划单独分区。
- **计划中心**：新增 `plan-center.vue`，默认收起，按活动/待处理/待验证/历史计数；展开后分区展示，
  其它会话的计划带来源跳转，历史区保留完整卡片与证据。
- **归档不是删除**：`softDeletePlan` 之外没有自动删除；归档卡片仍可展开查看步骤与证据，
  并保留 `run-now`（对终止目标走显式修订）。
- **会话检索**：`sessions-search` 输入按标题、预览、sessionId、最近消息文本过滤。
- **窗口能力**：`capabilities.stage` 派生自启动查询；表情工具在无模型时给出可解释拒绝与恢复入口。
- **输入位状态**：无会话/无 provider 时禁用主输入框并显示原因与恢复入口。
- **表面预算**：辅助区（问题卡、侧通道、计划中心）合计 `max-h-[40%]` 并可滚动。
