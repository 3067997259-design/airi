# 红石施工、局部维修与开放探索

日期：2026-09-15。状态：范围与设计已确定，尚未实施。上游：[能力深化总方案](./capability-deepening-plan.md)、[执行计划 §11](./minecraft-player-capability-execution-plan.md)。

本文供开发与验收使用，包含预设故障答案。游戏代理的盲测输入必须排除本文及对应对话。当前没有指定实际蓝图文件和测试地块，本轮不操作真机。

## 1. 阶段目标

她在给定平地内整理并布置 Litematica 蓝图，通过生存操作完成甘蔗机施工。随后观察运行，定位局部故障，做最小维修，并保存结果。

| 能力层次 | 本阶段范围 | 结果依据 |
| --- | --- | --- |
| 使用设施 | 触发收割、观察运输、读取箱子 | 真实动作与产物 |
| 照图建造 | 读取蓝图、备料、安排施工、核对结构 | 放置与配置符合目标 |
| 适配方案 | 在给定平地居中、选择朝向、预留操作空间 | 放置后的包围盒与可达站位 |
| 调试维护 | 定位本案例的信号衰减，实施并复测局部维修 | 原故障消失，其余功能正常 |
| 自主研发 | 小问题、小实验、经验记录 | 证据与认识，不要求复杂机器 |

前四层由这个有限场景覆盖。任意地形改造、任意农场诊断和大型工业网络仍需各自的能力证据。第五层为开放方向，不阻塞首阶段交付。

给游戏代理的任务是：

> 在指定地块内，居中搭建这份甘蔗机蓝图，并确认它能够正常自动收割、将产物送入箱子。

首轮工程假设：提供足够的建造材料、工具和少量通用维修材料，放在已知容器中。材料获取链不成为本次施工的前置任务。结构所需的基础开挖与临时支撑限制在施工区域内。

## 2. 现有基础与接入方式

`game_place` 已支持小批放置、放置面、潜行和 yaw。当前成功条件仍使用 `after === itemId` 与库存减少，尚未表达目标方块状态。红石粉的物品 ID 与方块 ID 差异也需处理。[当前实现](../../apps/stage-tamagotchi/src/main/services/airi/game-host/index.ts)

`movement/host-port.ts` 已透传区域方块属性。红石施工需要继续区分静态配置、运行状态和观测缺失，不能把属性存在视为功能验收完成。[控制端口](../../apps/stage-tamagotchi/src/main/services/airi/game-host/movement/host-port.ts)

外置模组增加 Litematica 适配边界。它读取蓝图和 placement，创建真实投影并返回结构化状态。主进程拥有施工目的、进度与维修策略。玩家输入沿用既有命令所有权，不另建写命令队列。

本阶段的“粘贴”指布置投影。真实结构由玩家操作建造。Litematica 的实体粘贴是直接生成结构的另一种操作，不作为生存施工验收。[官方说明](https://github.com/maruohon/litematica/wiki/Schematic-Pasting)

Litematica 是用户已指定的集成对象。实施前核对实际安装版本、MaLiLib 配套版本和对象生命周期。蓝图能力缺失时报告具体前置条件。本阶段没有选定其他新增依赖。

## 3. 蓝图、选址与施工

蓝图记录包含文件身份、内容摘要、版本、子区域、相对原点、方块状态与材料需求。保留原文件，后续维修作为独立差异保存。蓝图清单可参考 Litematica 已有的材料清单与结构核对能力。[项目文档](https://github.com/maruohon/litematica/wiki/Frequently-Asked-Questions)

选址先核对地块边界和可施工深度，再计算旋转后的完整结构包围盒。中心对齐以结构为准，包含子区域偏移。原点不一定是结构左下角。尺寸奇偶导致无法精确对齐时，选择最近的合法整数格位置并记录偏差。

候选朝向同时满足占地、入口、箱子可达性及维护空间。水路或基础需要下挖时，将下方空间纳入范围。场地不足则返回具体冲突，不截断蓝图。

施工按支撑、触及距离和后续操作空间安排顺序。先保留内部元件的安装路径，再封闭外层。为水流与可能触发活塞的部分安排施工阶段边界，避免未完成结构提前运行。

精确放置根据实际游戏放置规则选择物品、支撑面、点击位置、视角与潜行。正式操作后回读目标状态与库存。中继器档位、观察者朝向、活塞朝向、漏斗出口和箱子位置都进入结构核对。

静态配置与运行状态分开比较。朝向和中继器档位属于配置。脉冲引起的通电、活塞伸出等属于运行事实，不能用蓝图中的某一瞬间值永久约束它们。

暂停时释放输入，保存已核对进度、临时支撑和待完成步骤。恢复时读取现场差异后继续。投影身份与控制会话分开保存，只管理本任务创建的投影。

## 4. 功能观察与故障诊断

完成结构核对后进入功能验收。左端观察者侦测甘蔗长到三格高，触发活塞收割上部并保留根部。水流把掉落送到漏斗，最终进入箱子。

观察窗口覆盖触发、沿线信号、每个活塞、掉落运输和箱子增量。服务器记录有界区域内的 tick 与事件顺序，主进程批量读取。记录包含世界、维度、采样来源和完整性，读取遗漏不能被解释为信号为零。

初次测试可通过正常玩家放置甘蔗制造高度变化。先准备各列可收割的甘蔗，再触发左侧观察者。运行记录区分人工布置的测试输入与自然生长。随后补自然运行观察。等待超出预算时保留未完成项。

诊断沿触发、传输、执行、收集逐段定位。她自行比较正常列与异常列，提出候选原因，再用局部观测或小范围操作区分原因。工具返回真实状态与事件，不直接返回预设故障标签或维修答案。

### 验收侧夹具条件

用户指定的预设故障为一条 16 格红石线路，最右侧活塞无法获得有效信号。参考修法是在合适位置替换为最低档中继器。红石的传播距离限制支持这个案例，但具体结果仍取决于接线和供电位置。[Minecraft 官方说明](https://www.minecraft.net/en-us/article/redstone-dust)

夹具作者须先在目标版本核对：原结构确实存在末端失效，其他部分正常。夹具须有一个合法的局部中继器修复位置，且不会让另一列失去供电。各旋转或平移实例分别核对，不能只凭线路长度宣布故障成立。

盲测由独立游戏代理会话执行。输入白名单只包含任务、蓝图、普通工具和允许的通用知识。本文、测试预期、开发对话和带答案的记忆不进入检索范围。故障答案由验收进程持有，不能只依靠提示代理“不要看答案”。

## 5. 最小维修与蓝图差异

维修候选包含修改位置、原状态、新状态、材料、操作次序、理由和预期效果。先满足功能与施工约束，再比较改变的方块数量、额外材料和布局影响。夹具的参考修法用于评价，不要求她命中唯一坐标。

候选按单个方案顺序执行，执行前重新核对原状态。每次修改后完整复测。失败时只撤销仍能归属于本次操作且可安全恢复的修改，避免覆盖其他玩家的新改动。尝试次数和总时间受任务预算约束。

原始蓝图、施工进度、候选维修、已验收维修分别保存。候选只有在功能复测通过后才成为已验收维修。后续结构目标等于原始蓝图加已验收差异，施工器不得将中继器自动还原成原来的错误线路。

保存维修位置、原因、观测证据、适用版本与复测结果。她可以生成带版本的新蓝图供后续复用，原蓝图继续保留。单次修复经验只在已测条件下成立。

## 6. 验收与交付顺序

| 批次 | 交付 | 完成门 |
| --- | --- | --- |
| RS-1 | 蓝图清单、Litematica 投影、选址与朝向 | 结构居中且完全位于允许区域，箱子可达 |
| RS-2 | 精确施工、配置、进度与恢复 | 生存操作复刻结构，暂停恢复后不重复施工 |
| RS-3 | 触发与观测、功能验收 | 能区分结构正确与功能异常，观测缺失有明确结果 |
| RS-4 | 自主诊断、局部维修、差异保存 | 无故障提示完成维修，复测通过，恢复后不撤销有效维修 |
| RS-E | 可选的小规模实验与经验整理 | 保存问题、过程、结论和未解项，不作为 RS-4 的完成门 |

依赖复用 CD-0、地面站位、容器取物与精确交互。可先在给定平地推进，无需等待长距离寻路、鞘翅或完整长期目标系统。

首轮准备一个基准实例、两个位置或朝向不同的留出实例，以及一个没有该故障的正常蓝图对照。正常对照应通过验收且不产生无必要的维修。它用于排除“见到甘蔗机就加中继器”的固定脚本。

每个修复实例至少进行三轮受控触发。核对所有预期活塞动作、甘蔗根部保留、收集箱实际进货，以及其他列没有新故障。掉落留在水路、落在外面或被玩家拾取时单独记录，不算箱子收集成功。

保存原蓝图摘要、投影原点与旋转、施工差异、维修前后状态、触发轨迹、物料变化和结果。成功率附全部尝试数，不能只保存修好的那一轮。以上真机证据均待主流程采集。

## 7. 第五层：开放探索

第五层保留为自由探索的候选活动。她可以从使用体验提出一个小问题，例如延迟变化是否影响收割顺序，或怎样判断运输比收割更慢。当前实现先由明确任务入口启动，未来再接自主活动选择。

每次围绕一个问题，写出可检验的预期，在小型试验区改变有限条件，观察结果。记录采用“问题、假设、步骤、观测、结论、适用条件、未解项”。已有科学实验流程可参考 SciCrafter 的公开研究代码。[项目](https://github.com/scicrafter-bench/scicraft-bench)

实验具有场地、材料、时长和尝试次数预算。对照在可恢复的实验结构中进行，已验收设施继续保留。预算到达时保存发现与不确定性，清理临时操作并结束。

探索的有效产物可以是为一个条件提供证据、排除一个假设，或明确证据不足。结果不要求原创机器、复杂电路或性能最优。缺少证据时不能把猜测写成已掌握的规律。
