## 1. 目标与基线

目标：经审阅的技能在重启后仍可用，并在后续真实任务中持续减少重复劳动。
能力增长以实际复用和收益衡量，不以生成技能数量衡量。

[MODS](./MODS.md) 已记录 skill_submit、沙箱自测、静态分析、审阅通知、哈希绑定和反转文本示例的真机闭环。
当前 skills store 的 queue、catalog、revisionBatch 为内存 ref，并配置跨窗口 synced。
审阅队列由单一 localStorage owner 持久化，启动时会重新核对源码、工作区和审阅哈希；跨窗口同步不是磁盘持久化。
自测证据现在绑定 `selftest.mjs` 自身的哈希，导入时会验证自测文件，避免恢复带自测的技能时误把自测哈希当源码哈希。

## 3. 所有权与数据契约

skill-forge 拥有生命周期、源码审阅绑定与静态声明规则。
coding-host 拥有文件访问、沙箱执行和外部进程边界。
skills store 拥有可见队列与运行时注册投影，持久化只能有一个明确所有者。
memory 的 muscle 条目只能来自显式能力，停用或修订必须同步影响对应激活条件。

代码入口：

- packages/skill-forge/src/types.ts、lifecycle.ts、hash.ts、static-analysis.ts。
- packages/stage-ui/src/stores/skills.ts、stores/modules/memory.ts。
- apps/stage-tamagotchi/src/renderer/stores/tools/builtin/skill-submit.ts。
- apps/stage-tamagotchi/src/main/services/airi/coding-host/ 与 packages/coding-harness/src/ptc/。
- packages/core-agent/src/authority/、journal/ 与现有审阅卡、技能设置页。

不变量：源码变化使旧审阅失效；启动恢复不能直接相信磁盘 meta 自称 reviewed。
复用现有哈希与信任模型，不把它描述为强对抗安全证明。
外部执行器报告保留来源等级，不能自动充当本地变更与验证证据。

## 4. 实施批次

### SG-0：核对落盘产物与重启缺口

前置：DR-0、MD-0。

1. 从一次实际 skill_submit 追踪源码、自测、元数据、审阅决定和运行注册。
2. 检查 queue/catalog 的全部生产读写方，确认是否存在未记录的恢复入口。
3. 在隔离 profile 中提交、审阅、执行后重启，记录哪些状态保留或丢失。
4. 核对 muscle 条目与技能的稳定关联，确认 reject、quarantine 和内容修改的传播。
5. 与 MD-1 确定需要备份的技能数据，避免另设第二份目录所有者。

验收：形成可复现的恢复差距与最小存储清单。若已有恢复实现，记录并复用，不复制一套持久化。

### SG-1：技能审阅状态持久化与恢复

前置：SG-0；持久化边界与 MD-1 对齐。

1. 保存技能稳定标识、版本、源码位置、内容哈希、自测结果、审阅决定、隔离与启用状态。
2. 持久化写入和队列更新由单 owner 执行，其他窗口只接最小快照。
3. 启动时读取持久记录，核对实际源码、审阅绑定和自测产物，再注册可用技能。
4. 缺失文件、内容变化、损坏元数据或兼容性失败时进入可见待审或隔离状态。
5. 重复恢复不得重复注册工具、重复建 muscle 或重复发审阅通知。
6. 明确工作区切换时的目录归属，旧目录中的技能不能静默读取新工作区文件。

验收：批准后的未变技能重启可用；改过源码的技能不会继承旧批准；删除和隔离重启后仍有效。
多窗口同时操作只产生一次决定，远端快照不触发本地状态提案。

### SG-2：一个真正实用的技能毕业考

前置：SG-1、DR-1、MQ-2。

1. 从重复发生的真实任务中选择一个低风险动作，例如固定格式的本地检查报告。
2. 先记录不用技能时的完成率、人工步骤、耗时和工具调用数。
3. 让她提出技能、声明能力范围、运行沙箱自测，再交用户审阅源码与结果。
4. 在至少三个不同输入的后续任务中复用，包含一个失败或边界输入。
5. 重启后再执行一次，验证收益和恢复状态同时成立。

验收：实际结果正确且可检查；使用成本或人工工作量有明确变化；失败会报告具体原因。
反转文本例子可以保留为接线检查，但不能代替本批的实用收益证据。

### SG-3：经验到修订、停用与恢复

前置：SG-2；使用 MQ-2 的有效事实与反射边界。

1. 从真实失败或重复工作中生成有来源的修订候选，复用 dreamRevisionBatch 的有界队列。
2. 将候选、已批准技能和废弃技能分别表达，不把 dreaming idea 当可执行动作。
3. 源码修订使旧审阅失效，重新自测并审阅后才启用。
4. 拒绝、隔离或退役时同步撤销工具注册、prompt 激活和 muscle 触发。
5. 保留可恢复的旧版本及审阅记录；恢复前核对内容、兼容性和当前执行范围。
6. 记录修订频率、实际复用和维护成本，控制审阅队列规模。

验收：修订不会绕过审阅；已停用技能不被反射复活；失败上下文指向真实事件；用户能解释当前运行的是哪一版。

### SG-4：有需要时扩展外部能力

前置：SG-1/2。各子项独立，不能为一个适配器扩大整套插件兼容面。

| 子项 | 启用条件 | 实施与验收 |
| --- | --- | --- |
| opencode 代劳技能 | AIRI 遇到本地工具不适合的真实任务 | 核对当前 CLI 文档与仓库骨架，验证版本探测、参数、取消、超时与工作区；报告不能独立满足证据门 |
| 本地 RPC 通道 | 有已知本地服务的具体调用需求 | 登记服务和端口边界，审批本次动作，测试 POST、错误端口与拒绝路径；不放宽通用 fetch 的 loopback 规则 |
| 沙箱隔离升级 | 现有隔离无法满足已选技能的实际需求 | 调研候选并让用户选择，明确威胁模型、宿主桥与终止行为；不顺带改 MC 沙箱 |

外部代劳执行后，由拥有当前工作区的可信工具重新观察成果并验证。
dsh 内容插件运行时兼容保持取消。AIRI 自有技能格式和现有只读 task 子运行继续复用。
