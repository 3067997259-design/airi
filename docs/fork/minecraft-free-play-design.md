# Minecraft 自由游玩：兴趣、个人项目与自主活动

日期：2026-09-13。状态：用户确认方向后的设计草案，未实施。

目标：她在没有新指令时，也能依据真实经历选择活动。她记得自己的打算，能持续推进，也能暂停、休息和改变主意。

本文承接 [玩家能力缺口与实现路径](./minecraft-player-capability-gaps.md)。能力文档负责她能做什么，本文负责她为什么选择做、何时继续，以及经历如何影响下一次选择。

本文中的状态、字段与批次名称都是设计建议，不代表已有 API。本文不启动游戏，不开启自主运行，不改变既有批次排期。

## 1. 产品目标与首个场景

“自己想干什么”体现为可保留、可解释、可修订的打算。理由来自观察、需要、偏好和记忆，并在行动前记录。

首个目标场景：

> 她在营地附近发现一条河，自行决定沿河走一段。
> 她到达一个能看清河道的位置，记下那里。
> 回来后，她可以分享发现，也可以先不说。
> 再次进入同一世界时，她想起那个地方，决定继续查看，或者为以后建桥保留这个打算。

验收不要求她必定选择河流。其他符合实际观察、个人偏好与当前能力的活动同样有效。需要证明的是选择有依据、行动有结果、经历影响后续选择。

产品目标包含五种行为：

- 空闲时自行选出一项具体活动。
- 连续行动期间保留目标与选择理由。
- 遇到变化时调整活动，并保留未完成的进展。
- 在同一世界的后续游玩中复用经历。
- 自行结束一次活动，允许休闲、休息和放弃。

首批覆盖营地附近的有限游玩。自动通关、任意模组实验、完整野外生存和所有信道同时交互，分别依赖后续能力与交互批次。

## 2. 当前基础与接入缺口

依据本次工作区代码与既有记录。旧计划中的完成状态以对应验收记录为准，本轮未重跑。

| 基础 | 当前职责 | 本设计需要补充的内容 |
| --- | --- | --- |
| [生命模式主进程][life-host] | 心跳、配置、额度申请与冷却 | 借用调度与额度模式，为游玩选择提供有明确来源的入口 |
| [社交考量][life-store] | 当前通过 `self_decide` 选择开口、私记或沉默 | 保留社交职责，活动选择走独立的决策契约 |
| [MC-2 探索器][explore] | 对指定物品按固定来源顺序学习、实验与记录 | 接收个人活动提出的知识问题，不负责决定人生目标或任意实验 |
| [Flow][flow] | 自动推进已启动的任务 | 接收一次有界游戏活动，保留唯一自动推进职责 |
| [长期目标调度][long-goals] | 持久目标、等待、运行与结算 | 增加游戏作用域和自主来源，复用目标生命周期 |
| [game-host][game-host] | 领域工具与游戏控制 | 补观察语义、能力条件和活动所需的玩家操作 |
| [命令注册表][registry] | 命令身份、写动作互斥、租约、取消与回执 | 保留同一执行路径，将活动归属贯通至命令 |
| [世界记忆][world-store]与[知识分级][knowledge] | 世界来源、新鲜度、候选与实测知识 | 加入个人项目、地点经历与偏好变化的引用 |

三个现有边界需要显式承接：

1. [CONSIDERATION](./CONSIDERATION-PLAN.md)限定社交考量不能推进工作。自由游玩不能通过给 `self_decide` 挂游戏工具来接入。
2. 当前长期目标的 `checkStartConditions` 检查隔离工作区和工作区观察工具。游戏项目需要自己的环境条件，不能填入虚构路径绕过检查。
3. 当前游戏社交候选主要压缩异常结果，干净观察不会自然形成发现候选。自由游玩需要实际的环境变化来源。

## 3. 五种动机及其更新方式

| 动机 | 例子 | 依据与更新方式 |
| --- | --- | --- |
| 当下需要 | 食物不足，想先补给 | 使用最近游戏快照，相关数值变化即可重算 |
| 稳定偏好 | 喜欢沿河探索、木质建筑或收藏植物 | 初始角色描述提供起点，多次真实经历逐渐修订 |
| 好奇心 | 想知道陌生方块的用途，或河流通向哪里 | 绑定具体观察与知识缺口，解决后降低吸引力 |
| 个人项目 | 想在湖边修一座桥 | 保存项目、下一步和进展，可跨多次游玩 |
| 共同经历 | 想带你看看之前一起发现的地方 | 引用真实互动、人物身份和世界地点 |

偏好可以先用“弱、中、强”及置信程度表达。首批不设复杂情绪数值或固定奖励公式。每次修订保留旧值、理由和经历引用。

偏好更新需要区分原因。喜欢的活动暂时做不了，不表示不再喜欢它。一次遇险也不足以让她永久回避整类玩法。

用户反馈是偏好线索之一。“这花好看”可以增加她对这种花的注意，但不会自动建立收集任务。她自己的游玩评价与重复经历也参与更新。

首次游玩时，系统从现有人格提取少量候选偏好，再结合现场生成活动。没有相关偏好时，可以先选一项可行的小范围观察，并保留选择依据。

## 4. 状态模型与持久化边界

### 4.1 对象与生命周期

| 对象 | 含义 | 生命周期与归属 |
| --- | --- | --- |
| 偏好 | 她倾向于选择的玩法、风格和对象 | 随角色保留。世界中的坐标不写入全局偏好 |
| 愿望 | 值得以后做的事，可以暂时缺少条件 | 保留来源、吸引力和缺少的条件，不直接运行 |
| 个人项目 | 她已承诺推进、通常需要多次活动的愿望 | 映射到现有持久目标，保存项目版本与世界作用域 |
| 活动 | 本次准备做的一件有界事情 | 映射到一次 TaskRun 与 Flow，也可以独立于个人项目 |
| 动作 | 移动、观察、采集或合成等具体操作 | 使用现有 game-host 命令和租约 |
| 地点经历 | 对营地、河岸或其他地点的观察与评价 | 绑定世界、维度、坐标、来源与观察时间 |

“有愿望”不表示“必须建项目”。沿河散步可以是一次活动。若她后来想多次返回并修桥，再将它发展为个人项目。

愿望、项目和地点记录复用既有计划与记忆存储。结构化活动状态负责恢复，语义记忆负责召回。向量搜索结果不能直接充当当前执行状态。

### 4.2 一次选择需要保留的信息

| 信息 | 用途 |
| --- | --- |
| 选择身份与来源 | 区分自主选择、用户任务和恢复活动，不伪造用户消息 |
| 相关项目及版本 | 防止旧选择继续推进已修订项目 |
| 候选活动与选择理由 | 保留当时的依据，不在结束后补写动机 |
| 观察和记忆引用 | 能追溯她看到了什么、想起了什么 |
| 世界、玩家与配置版本 | 提交行动前核对环境与自主范围 |
| 期望结果与下一步 | 表达本次做到哪里即可结束 |
| 需要的能力与资源 | 区分缺接口、缺材料、条件不足和未知 |
| 暂停条件与再次考虑条件 | 防止无限等待或反复失败 |
| 活动结果与个人评价 | 分开保存游戏事实、完成程度与喜好 |

模型可提出活动与理由。宿主签发执行身份，并核对世界、版本、能力和预算。模型不能通过修改这些字段扩大自主范围。

### 4.3 活动状态

以下是业务语义，实施时映射现有 TaskRun、Flow 和计划状态，不复制一套运行状态机。

| 状态 | 含义 | 后续行为 |
| --- | --- | --- |
| 候选 | 有吸引力，尚未选择 | 可以保留、合并或过期 |
| 就绪 | 已选择，具备下一步 | 申请唯一运行权，刷新环境后执行 |
| 执行中 | 本次 Flow 正在推进 | 新发现先记录，在合适边界重新考虑 |
| 等待条件 | 缺材料、能力、时机或环境 | 只在相关变化或到期时复查 |
| 暂停 | 活动被用户或其他任务挂起 | 依据暂停来源决定能否自动恢复 |
| 已结束 | 达到本次目的、主动结束、失败或取消 | 保存结果和原因，结束原因不等于成功 |

休息可以作为明确选择，记录再次考虑时间或条件。休息期间不占用游戏写锁，也不循环调用模型。遇到实际危险时仍由反射处理。

## 5. 从观察到选择

```mermaid
flowchart LR
    A["世界变化与相关记忆"] --> B["候选活动"]
    B --> C["选择或延续一个打算"]
    C --> D["申请运行权并刷新条件"]
    D --> E["Flow 与领域动作"]
    E --> F["核对游戏结果"]
    F --> G["更新进展、经历与偏好"]
    G --> B
```

### 5.1 观察提供具体对象

候选来源包括首次进入世界、附近发现、活动结算、资源变化、相关项目条件满足，以及到期的休息。

自主观察需要补齐以下内容：

- 带来源、观察时间、范围和截断说明的附近方块、实体与地形摘要。
- 已访问地点与当前可到达方向，区分实际观察和路线推测。
- 背包、装备、补给与工具能力摘要。
- 当前活动、未完成项目，以及与现场相关的少量记忆。

观察范围限于当前工具实际取得的信息。任意远处的实体或未观察区域，不能因为宿主能查到就自动进入她的兴趣列表。

审美活动可按需取得游戏画面。同一地点的重复读数不自动算作发现，实际状态变化仍可产生新事件。“河道拐弯后有什么”保持为问题，直到实际观察。

### 5.2 产生少量候选

一次选择先产生三至五个候选。这个数量是首批调试起点，最终阈值按实测调整。候选覆盖当前项目、必要补给和现场机会，也允许选择休息。

每个候选需要一条来源明确的理由和一个可行的下一步。无法执行的愿望可以入册，但不能成为当前活动。

同一项目、地点和目的的候选合并。改写一句目标描述，不能绕过重复活动与失败抑制。

### 5.3 模型选择，宿主核对

模型比较紧迫性、兴趣关联、预期新发现、项目延续价值、风险、成本和重复程度。首批保留定性理由，不将未经校准的加权分数当成真实效用。

选择契约支持开始、继续、等待、休息和结束。模型选择结束时，还需说明达到目的、玩够了、暂时放弃或遇到阻塞。

宿主在提交动作前再次读取关键环境。候选生成后发生的换世界、用户暂停、材料丢失和工具撤销，都能使选择失效。

无效模型输出记为决策失败，不解释为休息。重试服从同一预算和次数上限。连续失败进入等待，不自动选择随机游戏动作。

### 5.4 保持连续，也允许改变主意

当前活动只要仍可行且有进展，就保留延续价值。普通新发现先放入候选，避免每次观察都中断路线。

活动完成、路线失效、资源不足、危险变化或明确用户请求，可以触发重新考虑。主动切换必须记录放下什么、为什么，以及以后何时再考虑。

同一原因导致的重复失败进入等待条件。只有材料、能力、位置或其他相关前提改变后才重试。一次工具调用次数增加，不自动表示取得了新进展。

## 6. 调度、预算与唯一执行入口

### 6.1 所有权

| 所有者 | 职责 |
| --- | --- |
| 主进程 | 自主配置、唤醒、原子额度申请、活动运行权与撤销 |
| leader | 构造有界上下文，调用模型选择，通过现有入口启动 Flow |
| Flow | 推进一次活动，处理工具结果与任务结算 |
| game-host | 领域命令、游戏绑定、写锁、租约与回执 |
| 客户端模组 | 实时移动、交互、反射与输入清理 |
| 计划与记忆模块 | 持久项目、进展、来源和相关经历 |

自由游玩增加领域决策职责，不新增第二个自动执行循环。已有活动运行时，调度只合并相关事件，不再启动另一条 Flow。

主进程复用 [长期目标宿主][goal-host]的唤醒与单次运行模式。通用运行申请需要协调自主活动、用户任务和既有长期目标，不能各自持有互不相知的运行锁。

长期目标的环境检查按目标作用域分派。代码目标保留工作区检查，游戏目标核对玩家、世界、当前连接与工具能力。两个分支都使用现有生命周期与结算规则。

### 6.2 事件与额度

首批采用事件驱动，辅以低频心跳复查等待项。短程动作和实时保命由已有执行器完成，模型不逐 tick 决策。

生产入口不调用 MC-2 探针的 `requestTestHeartbeat`。心跳仅提供考虑机会，实际调用前由主进程核对来源、事件新鲜度和额度。

额度区分一次候选选择、Flow 中的模型调用和可选的经历整理。所有实际调用都计入可见预算，不能只计算最初选择。沉默不免除已发生的模型成本。

同一事件重复广播不重复领取额度。没有相关变化时不调用模型。初次进入、到期等待和用户恢复本身是明确事件，可以启动一次新的观察与选择。

模型预算耗尽后停止新规划。已提交的命令仍按原期限、取消和反射契约收敛，沿用 MC-1b 行为。执行前要为该活动预留有界收尾空间，不能靠无限续费完成收尾。

### 6.3 自主配置

自主配置保存启用状态、允许的世界与玩家、活动范围、资源限制、模型预算和恢复规则。具体字段在实施批次中定稿。

用户开启后，她在配置范围内自行选择。范围之外的愿望可以保留，不能自动扩大配置。共享建筑、玩家物资与其他玩家的交互按已配置范围判断。

社交静默与游戏暂停分别处理。关闭主动表达后，已允许的游戏活动仍可继续。现有社交静默时段不能不加区分地套到所有活动上。

## 7. 中断、恢复与用户交谈

| 事件 | 当前活动 | 恢复方式 |
| --- | --- | --- |
| 普通聊天或偏好表达 | 保留活动，可记为相关线索 | 不因一句聊天创建新任务 |
| 明确的游戏任务 | 在可停止边界挂起自主活动，保留实际进展 | 用户任务结束后，按配置重新考虑旧打算 |
| 用户暂停自由游玩或在该活动中说“停下” | 先阻止新命令，再取消当前命令 | 等待明确恢复，不被下一次心跳重新启动 |
| 用户取消个人项目 | 终结项目，取消相关活动 | 不自动复活同一项目 |
| 反射抢占 | 反射接管输入，原命令按既有契约结束 | 稳定后重新读取环境，再决定继续、返回或等待 |
| 其他工作取得执行权 | 挂起游戏活动，不再派发动作 | 执行权释放后依据配置复查 |
| 死亡、断线或维度变化 | 终结旧运行，保留已核对的事实 | 重新取得绑定，不能重放旧命令 |
| 应用重启或 leader 更替 | 旧运行先结算或标记中断 | 取得新运行权后，从最新世界状态重新规划 |

取消请求与已停止分开记录。旧动作可能已经产生效果，迟到回执仍可补全原活动的事实，但不能启动新活动。

活动身份、项目版本、运行身份与命令身份分别关联。切换世界后的回执不更新当前世界进展。无稳定世界身份时，跨连接地点只能作为历史，不自动恢复坐标活动。

普通聊天与任务修订的区分放在交互归属入口，承接 [多信道设计](./multichannel-scenario-design.md)。现有 Flow 会在部分路径中将排队文本作为 steering 消费。首批不能声称已经支持完整的边走边聊。

首批可在活动边界处理普通对话，明确停止仍立即进入取消链路。后续多信道接入完成后，再验收独立交谈、游戏修订与执行并行。

## 8. 经历如何改变下一次选择

活动结束后，先核对事实，再保留个人评价。例如“到达河岸”是游戏结果，“我喜欢这里的视野”是她的评价，两者引用同一段经历但具有不同含义。

经历整理只在值得保留的边界运行：首次发现、明显成功或失败、项目进展、共同经历，以及明确的偏好修订。普通位置轮询不逐条生成长期记忆。

整理结果可以更新地点记录、项目下一步、知识问题和偏好。重复整理同一组事件不增加独立经历次数。模型的私记和自述也不能反复成为新的外部发现。

未知机制交给 MC-2 获取候选并实测。读懂一段指南不证明能操作机器。所需玩家能力缺失时，项目保留等待条件，知识保留相应来源等级。

需要固化为技能的活动仍走现有审阅与撤销流程。自主游玩不会自动批准新代码，也不直接注册原始 MCP 写工具。

### 8.1 休闲活动的结束条件

| 活动 | 可核对的结果 | 个人评价 |
| --- | --- | --- |
| 沿河散步 | 到达本次选择的观察点，取得新观察或明确返回 | 是否喜欢这条路线，以后是否想再来 |
| 看风景 | 取得指定位置的有效画面或环境信息 | 喜欢的对象与原因，不虚构未出现的景物 |
| 陪玩家走一段 | 在指定范围内跟随，停止时记录位置和原因 | 是否想继续陪伴，可以暂时没有其他项目 |
| 研究陌生方块 | 保留观察、候选解释和实测范围 | 还想弄清的问题，或者暂时失去兴趣 |

这些活动不要求物品增长。结束原因可以是“本次看到这里”。期望未满足但主动结束时，保留未完成结果，不借用成功状态。

## 9. 首版实施顺序

以下为本设计内部的依赖顺序，不调整 MC-3、能力补齐与多信道的既有排期。

| 阶段 | 交付 | 进入下一阶段的依据 |
| --- | --- | --- |
| F0 观察与选择记录 | 补环境摘要、能力条件和候选选择。只记录决定 | 候选有来源，重复观察不重复决策，未知保持未知 |
| F1 一次自主活动 | 选择接入原子运行申请与 Flow。只用已有且通过场景核对的动作 | 没有新用户消息也能开始并结算活动，取消后不自启 |
| F2 连续打算 | 个人项目、地点经历、等待条件、跨会话恢复 | 两次游玩之间保留进展，世界切换与重启不重放旧命令 |
| F3 经历影响偏好 | 有来源的偏好修订、习惯化、休闲与主动结束 | 行为体现经历变化，又不会因单次反馈完全改写偏好 |
| F4 拓展游玩 | 接入补齐后的生产、战斗、移动、MC-2 与交谈能力 | 每种玩法有可执行条件，长期项目可由多个活动逐步推进 |

F1 的夹具提供营地、基础补给和少量可行方向，并明确记录外部准备。只允许小范围观察、短程移动、有限采集和可用的简单合成。

工作台、装备补给和容器未补齐前，夹具不能被称为完整自主生存。沿河、建桥和远程狩猎等项目，需要分别满足 [能力清单](./minecraft-player-capability-gaps.md)中的前置条件。

每项活动模板只描述能力、前置条件和可核对结果。模板可以扩展，不能变成规定每天必须执行的固定日程。

### 9.1 建议代码落点

| 落点 | 建议变更责任 |
| --- | --- |
| `packages/core-agent` 既有计划与运行边界 | 自主来源、游戏作用域、项目与活动归属、完成语义 |

本轮不选择新依赖。实施前先搜索现有实现。确有依赖缺口时，再按仓库规则调研候选，并由用户参与选择。

## 10. 用户能看到什么

日常界面只需表达她现在想做什么、做到哪里，以及是否在等待。详细的候选、来源、额度与命令关联放在诊断视图。

“为什么去那里”的回答引用行动前的选择记录。如果她后来改变主意，分别说明最初理由和后续变化。

活动成功不强制产生发言。值得分享的经历进入社交候选，由现有表达流程决定是否开口。当前活跃 Flow 的社交门控继续生效，不能为分享绕过它。

用户可以暂停自由游玩、取消项目和修订活动范围。角色可以保留兴趣，但执行始终服从当前配置。

## 11. 验收场景与评价方法

以下是未来验收设计，本轮没有新增或执行这些测试。自动化范围沿用 [Vitest 规则](../../.agents/skills/enforce-rules-for-vitest/SKILL.md)。

| 场景 | 需要证明的行为 | 主要方式 |
| --- | --- | --- |
| 初次自主选择 | 无新用户指令，候选引用实际观察，选出可执行活动 | 固定世界与真实模型 |
| 多样但有依据 | 相同现场可有不同合理选择，每种选择都能追溯理由 | 多次模型运行，保留候选与选择分布 |
| 延续个人项目 | 再次进入同一世界，召回项目并重读条件后推进 | 跨会话真机 |
| 新发现不频繁打断 | 路上普通发现入候选，当前可行活动保持连续 | 自动化事件场景与真机 |
| 缺能力或材料 | 记录等待条件，无变化时不重复尝试 | 自动化与真实失败回执 |
| 条件满足后重试 | 材料或能力实际变化后，重新考虑相关愿望 | 自动化与真机 |
| 用户停止 | 当前活动取消，后续心跳不重新启动 | 自动化取消链与真机 |
| 普通聊天 | 偏好线索不变成采集任务，不误取消活动 | 交互归属测试，按阶段验收交谈 |
| 重复事件与多窗口 | 同一事件不重复花费额度，一个活动只有一个执行所有者 | 宿主与多窗口自动化 |
| 重启与迟到结果 | 旧结果只补原活动，恢复不重复发射、采集或合成 | 自动化，配合真机重连 |
| 世界身份不足 | 历史坐标不被当作当前可直接执行的目标 | 双世界与连接切换 |
| 预算耗尽 | 不再规划，当前命令按期限与取消收敛 | 可控时钟与真机 |
| 偏好缓慢变化 | 单次夸奖或失败不完全改写偏好，多次经历可产生修订 | 固定经历输入与多次模型运行 |
| 防止自述循环 | 同一经历多次整理不增加发现次数或重复提升兴趣 | 自动化来源与去重 |
| 休息和主动结束 | 有明确原因，不占写锁，不伪造成功或无限等候 | 自动化与真实活动 |
| 结果与评价分开 | 看风景可结束，虚构景物不能成为事实记忆 | 图像或环境证据与记忆核对 |

硬性行为要求零违反：世界与身份隔离、重复执行、用户停止和预算边界。候选是否合法、调用是否去重、恢复是否重放，通过稳定公共边界断言。

玩家感按连续场景评价。观察理由是否具体、项目是否延续、经历是否影响后续选择。另记录活动切换频率，以及休闲是否自然。记录原始次数和失败类型，不用“模型说自己像人”作为通过依据。

首批记录每段活动的时长、模型调用量、重复失败、切换原因与实际成果。探索距离和物品数量仅作诊断，不能成为唯一优化目标。只追求数量会挤掉休闲与共同经历。

自动化不固定要求模型选中某条河或某种物品。固定场景用来核对条件与结果，多次模型运行用来观察选择质量。长期偏好与跨日连续性必须另做真实时间场景。

## 12. 设计依据与待定项

[Voyager](https://arxiv.org/abs/2305.16291)提供自动课程、技能积累与环境反馈的研究依据。本文借鉴按当前能力选择下一项挑战的机制，并加入个人偏好、休闲和共同经历。

[Generative Agents](https://arxiv.org/abs/2304.03442)研究记忆、反思与规划对行为连续性的作用。本文用真实游戏经历形成后续打算，不采用虚构日程填补素材。

以上论文支持机制参考，不证明本设计已经具备玩家感。具体效果需要本项目的多次游玩记录。

实施阶段再确定候选上限、偏好修订阈值、观察范围和心跳间隔。活动时长与分阶段预算也在实施时定稿。参数先在小范围夹具中核对，再扩展至真实生存场景。
