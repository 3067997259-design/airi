# 烟花配方与助推预约修复（2026-09-27）

最终部署：0.2.90+1.21.1；零提交。跳过 lint、typecheck、Vitest；定向 Java 20/20，单版本低并发构建成功。

## 根因与改动

1. 旧 35 tick 来自等级 2 的一次标定，误用于所有配方。当前原版字节码保存在 firework-bytecode.txt：lifetime = 10 × (1 + flightDuration) + nextInt(6) + nextInt(7)，服务端在 life > lifetime 时结束。等级 1/2/3 对应寿命阈值 20–31 / 30–41 / 40–51 tick；完整更新次数多一次。它们不是固定 1/2/3 秒。客户端首见年龄也不等于服务端生成年龄，不能把名义寿命当作保证。
2. FlightRocket 统一名义值与配方范围。FlightDynamics.Input 携带本次点火时长；控制器从实际点火手读取 FIREWORKS 组件，航路、恢复和落地会话用同一来源。已附着实体从 getItem 读取配方，不用当前库存猜上一发。缺失组件按原版零等级处理。
3. 实体仍在时估计至少为 1；只有实际未观察到附着实体才归零。冷却继承改用首见年龄，不再用 35 减剩余时长反推。逐 tick 增加 rocketFlightDuration / boostFlightDuration。
4. 预约逐 tick 对比实测余推与预约模型。变化时同 tick 撤销陈旧任务，回到实测状态选动作；不放宽 origin 采纳容差。rocket-before.txt 保存修前回归失败，rocket-final-tests.txt 为 20/20。
5. 0.2.89 三级实测发现晚熄火时余推卡在 1，连续消耗任务名额；0.2.90 在该状态等待实际熄火，回归验证等待十 tick 后仍可使用第一个搜索名额。

## 尚未解决与下一步

- 当前预测仍是配方相关的名义轨迹，尚未对每个可能熄火 tick 的轨迹分支全部验证。maximumTicks 扩展的是观察时域，不等于证明长短两端及中间所有寿命都安全。不能将本批称为随机寿命的完整鲁棒解。
- 下一批应将末段入口改为受约束的状态集合：对可能熄火时刻分支验证可继续的进近，并在实际熄火时选择对应分支或从实测状态重算。禁止依靠扩大位置/速度容差吞掉误差。优先减少末段不必要的新点火，检查完整助推到减速落台的可行性。
- 等级 3 的闸门高度越界需要入口能量约束；等级 2 的最后弯低速/低高度拒绝需要可行进近，不能仅改 A* 评分。后台 300 ms 与主线程 12 ms 预算仍保留。
- TS host flight/simulation.ts 仍保留旧等级 2 的 35 tick 标定，未在本批改动；本轮冻结路线由 Java 原生执行，不能推导 TS rollout 已同步支持各配方。后续恢复主机 rollout 前必须补齐配方输入和跨语言回放。
- 原桥面到洞内 AIRI 正常动态路线仍未通过。局部固定路线成功不能代替它。
