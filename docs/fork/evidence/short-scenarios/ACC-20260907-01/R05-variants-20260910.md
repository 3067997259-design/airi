**没有混用旧指纹向量**：指纹已在 `sourceFingerprint` 里换成新模型名，检索直接返回空集，而不是把

### 观察：记忆为空时模型改走工作区

该轮回答仍然是 `R06-SYNC-A-20260909`，但 journal 显示它先 `grep` 再 `read`（`seq=7..10`）——
答案来自 workspace 里的证据文件，不是记忆。也就是说：**用户看不出这个答案来自记忆还是来自翻工作区**。
这与 M07 记录里「避免工作区检索替代记忆」是同一类观感问题，本次只记录，不判 R05 失败。

### 还原

把模型改回 `voyage-4-large`：迁移 `state: "complete"`、`nextIndex: 20 / total: 20`、无错误；
再开新会话 `BNk8TgJS4Ng707ui53E4p` 问同一句：

```
memory/retrieved  memoryIds=["656b0f6f-…","90673864-…"]     ← 与基线一致
答案：R06-SYNC-A-20260909
```

**结论**：切换是显式的（状态 + 错误可读）、不混用旧指纹向量、还原后可恢复；变体 1 PASS。

## 变体 2：凭据缺失 —— 不满足「可解释的未配置提示」（新缺陷）

环境：`restores\restore-J2TLrx`，`auth: false`、`userId: "local"`、`activeSessionId: ""`（恢复出来的会话属于原 owner）。

### 观察到的问题

1. **聊天输入框照常可用**：占位符「说点什么...」，输入文字不会被拦。
2. **发送静默弹回**：输入「你好，请回复一句话。」按 Enter 后，草稿**仍在输入框里**，没有错误提示、
   没有 toast、console 无输出。直接调用 store 才拿到真实原因：

   ```
   chat.send(...) → ERR: Failed to load the target chat session
   ```

   `InteractiveArea.vue:173-189` 的 catch 在这个条件下把草稿还原（`messageInput.value = textToSend`），
   所以用户看到的是「按了没反应」。
3. **首屏的恢复说明也消失了**：这个副本早先已被 adoption（`effectsHeld: false`），而
   `step-welcome.vue` 的 `showRestoreNotice` 以 `restoreEffectsHeld` 为条件，于是 onboarding 退回
   「欢迎来到 AIRI！…配置您自己的 AI 服务来源」的全新安装形态——**没有任何地方告诉用户
   「数据已恢复，请登录 <owner>」**。

### 期望与关闭条件

- 未登录 + 存在 `restoredOwner` 时，即使已经 adoption，也应给出明确原因与登录入口（把
  `showRestoreNotice` 的条件从「hold 中」放宽到「未认证且知道恢复的 owner」）。
- 聊天输入框在「没有可用会话/未登录」时不应表现为可用：要么禁用并说明原因，要么发送失败时给出
  可见回执（复用同一句「数据已恢复，请登录 <owner>」）。
- 关闭条件：未登录恢复副本里尝试发言，能看到一句可读的原因，而不是草稿静默弹回。

记录见 [FIX-LIST-20260910.md](./FIX-LIST-20260910.md) 新增条目。
