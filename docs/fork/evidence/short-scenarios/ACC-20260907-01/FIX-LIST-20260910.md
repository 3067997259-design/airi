### 17. `createSession` 不校验 characterId（低，调用方误用触发）

- **现象**：`createSession(characterId, options?)` 的第一个参数是 characterId；误传 `{}` 会把会话 meta 写成

  理由却是 `The current user or character is outside the goal scope.`——没有指出计划作用域本身是坏的。
- **期望**：非字符串直接拒绝；拒绝理由区分「作用域损坏」与「当前用户/角色不匹配」。
- **状态（2026-09-11）**：已修。`createSession` 对非空字符串以外的 characterId 抛 `TypeError`；长目标的 scope 不是非空字符串对时，`checkStartConditions` 报「goal scope is invalid，重建目标」而不是「outside the goal scope」。回归见 `session-store.test.ts` 与 `long-goals.browser.test.ts`。

## 三、环境备忘

- **判断当前跑在哪个 profile**：看 **renderer** 的 `--user-data-dir`（主进程命令行不带该参数）。
- **切 profile**：`APP_USER_DATA_PATH=<dir>` 启动。注意应用自己在跳进恢复副本时会写这个变量并 `app.relaunch()`，新进程会继承；要回默认 profile 必须显式清掉它。
- **恢复副本**：`Restore ZIP` 点按钮**不弹对话框**，要直接给隐藏的 `input[accept*=zip]` 赋值；`Backup ZIP` 反而会弹原生保存框（需人工点）。
- **agent-browser**：stdout 接管道会无限挂死（上游 #1308 / #1713）。用文件重定向 + 硬超时包装（`Start-Process -RedirectStandardOutput` + `WaitForExit(超时)` + `Kill()`）。
- **磁盘**：本轮 C 盘曾经写满（ENOSPC）导致一次文档写入失败。恢复副本会持续占空间，当前有 `restore-J2TLrx`（含 14MB `restore.zip`）、`restore-7IF4GT`、`restore-2CLTVP`、`restore-uugF7G`，以及 `D:\airi\.tmp\profile-s10-scratch`。不再需要时可以清理。
- **重建**：`pnpm -F @proj-airi/stage-tamagotchi build` 即可（stage-ui 的 exports 指向源码，无构建步骤；`core-agent`/`i18n` 走 dist，改了它们要另外 `pnpm -F <pkg> build`）。
