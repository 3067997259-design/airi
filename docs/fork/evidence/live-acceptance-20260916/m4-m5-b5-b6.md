# M-04 / M-05 / B-05 / B-06 真机验收（用户配合，2026-09-17）

环境：bot 客户端 0.2.28、服务端桥同批构建；用户 `AfterRain`（创造）与 bot `airitest` 同服。
夹具：石堆 3×3（x257..259、y201、z−33…−31）；bot 手持石镐；用户持有弓 + 64 箭 + 鹅卵石。

## M-04 他人同时挖同一区域 — PASS

- **M-04a**：用户先挖掉 (259,−33) 且不捡掉落；bot 挖 (257,−31)（要求产出 `cobblestone`）。掉落就在同区（现场 3 个 cobble 实体）。
  - bot 鹅卵石 1→2；账本 **`count 1, lowerBound 1, fuzzy 0, evidence server-attributed`**：只记自己那块的可证明产出，同区他人掉落不计入、也不误记成已收数量。
- **M-04b**：用户站在 (257,−33) 方块上；bot 从北侧挖掉它，掉落被用户自动拾取。
  - bot 鹅卵石 2→2；**`endReason broken_no_product`、`count 0, lowerBound 0, fuzzy 1, evidence server-attributed`**：服务端有产出事实、库存未证实 → 记为模糊量，不伪造产出。
- 说明：一次尝试中掉落因随机落点偏出自动拾取半径，窗口内未收取，账本同样给出 `lowerBound 0 / fuzzy 1`（不写成"已收取"）。另：`game_break` 不走位（`out_of_reach`），需先预置位置/`move_to`；首次换工具出现一次 `data_unavailable`（`equip did not verify ... (read none)`）瞬态，重试即通过。

## M-05 他人扔物、实体合并、拆分、被捡 — PASS

- 用户朝 (257,−32) 右键扔 5 个鹅卵石（落地成 4 个实体，过程中含拆分与合并）；bot 挖掉该块并收取。
  - bot 鹅卵石 2→3；账本 **`count 1, lowerBound 1, fuzzy 0, evidence server-attributed`**：他人物品（4 个实体）不被计入本次产出。
- 实体变化观测：4 个实体 → 剩 2（1 个被 bot 收取 + 1 次合并），实体合并未影响账本。
- 被捡场景即 M-04b（他人先于 bot 拾取 → 模糊量、不伪造）。
