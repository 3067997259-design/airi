## 落点实测（下垂验证）

夹具：目标位 (43.5, 142, −37.5) 处的 3 格高石墙；从 (43.5, 141, −57.5) 用模组任务连续 3 发（瞄准墙中部 y142）。

- 三支箭的停留位置 y = **141.0066 / 141.0067 / 141.0069** → 20 格处**下垂约 1 格**；若对准平地上羊的中心（y141.65），箭头在到达前扎进地板（y141 面），因此 20/40 格平地命中率为 0。
- 上坡（目标 +10）时下垂使箭头偏低 → 4/10；下坡（高台→主平台）时下垂与下降对齐 → 10/10、9/10。
- 所有回执的 `closestDistance 0` 是**宿主弹道解的预测**，与客户端实际瞄准（无重力补偿的线性预判）不一致。

## 结论与记录

- **B-01 PARTIAL**：10 格平地 100%、下坡 10–20 格 90–100% 可用；平地 ≥20 格与上坡条件在当前客户端瞄准下不可用。≥30 发/关键条件的首轮要求未达到（本批 10 发/条件）。
- **B-09（残差）部分覆盖**：实测下垂量（20 格约 1.0 格）与预测残差、命中率随距离/高差的变化已记录；正式标定待客户端瞄准接线后进行。
- **F-08 候选（记录在清单）**：客户端 `aimAtTarget` 线性预判 + 固定初速、无重力补偿；回执的弹道解（预测命中、`closestDistance 0`）不是实际执行路径。20 格平地命中率 0%，上坡偏差更大。
- 证据：[b1-range.json](./b1-range.json)（矩阵逐发）、[b-drop-probe 控制台记录]（落点）。脚本 [b1-range.mjs](./b1-range.mjs)。

## 地形避让复验（客户端 0.2.19 + 宿主走廊接线）

两步实现：

1. **客户端**：候选弹道逐拍用客户端世界的方块碰撞射线（`Level#clip`，COLLIDER）检测；被挡候选作废，评分优先未遮挡命中，其次未遮挡最近接近，最后才轮到被挡候选（射向不可达目标时的最小损失）。
2. **宿主**：射击前读取眼到目标走廊的区域方块（`get_blocks_region`，含空气），缺失格视为 `unknown` 并按遮蔽处理（CD-0 D10）；`isObstacle` 传入 `planShotFromObservation`，解不出干净弧线时按既有逻辑返回 `no_ballistic_solution` 并保留弹药。

## 本轮发现的记录

- **F-08（已修）**：客户端瞄准无重力补偿；20 格实测下垂约 1.0 格。修复见上。
- **F-09（待设计迭代）**：命中后目标的**击退残速**进入线性预判，预判量 = 速度 × 整个预测飞行时间 → 瞄准点被推过静止靶（实测 z 漂移 −17.5 → −16.01 → −15.88；−25.5 → −26.45），靠墙时被推入方块导致整组 `no_ballistic_solution`。验收夹具用击退抗性规避；真实修复属 CD-B2 目标模型（速度衰减或地面目标预判上限）。
- **F-10（条件无效）**：靶道“主平台 → 下方平台”组的目标在主平台悬挑下（主平台足迹覆盖到 z −15/−14，目标 z −15.5），任意直线或抛物都必须穿过主平台地板。探针实测：箭在射手前约 1.5 格落地并被 bot 自动捡回（箭矢计数 64 → 64），20 格内无箭、无伤害。该组从该站位不可达，非缺陷。
- 射墙探针在地形避让开启后不再是残差夹具：瞄准点在墙后时所有候选被挡，求解退化为“最近接近”，箭会越过墙顶。垂距残差以接线前的 y141.00 → 接线后 y141.5 记录为准。
