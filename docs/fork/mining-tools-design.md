# 工具选择、采掘资格与工具升级

日期：2026-09-14。状态：设计。依赖：[CD-0](./capability-deepening-plan.md) 与 [地面走廊](./movement-corridor-design.md)。

## 1. 现状与目标

`game_break` 已有单块生存破坏、距离预检和结果轮询。`game_collect` 可以接近方块、破坏并拾取。地形执行器也支持 `canDig`。三条路径尚未共享工具资格、耐久和掉落目标策略。

这会造成空手或错误工具长时间挖掘，以及方块消失但没有得到所需材料。当前 `game_break` 的方块 ID 变化也不能单独证明是自己完成了破坏。

源码：[game-host/index.ts](../../apps/stage-tamagotchi/src/main/services/airi/game-host/index.ts) 的 break/collect、[movement/executor.ts](../../apps/stage-tamagotchi/src/main/services/airi/game-host/movement/executor.ts)。模组为 `InteractHandlers.interact.breakBlock` 和 `BotController.startMining`。

## 2. 候选与选定方案

| 方案 | 收益 | 局限 | 决定 |
| --- | --- | --- | --- |
| 静态“方块 → 工具”表 | 原版常见场景简单 | 忽略状态、数据包、附魔和模组规则 | 仅作说明与已知候选索引 |
| MC-2 知识卡决定资格 | 能解释玩法 | 文本可能陈旧，不能保证掉落 | 用于配方和升级建议 |
| 游戏运行时资格 + 领域经济策略 | 适配实际规则，能解释取舍 | 需扩展观测原语 | 选定 |

运行时决定“这把工具能否获得预期掉落、实际破坏进度”。领域策略决定“是否值得花耐久、是否先升级”。

## 3. 采掘评估契约

模组提供无副作用的单块采掘评估。输入为方块位置、预期产物、允许消耗和候选库存范围。输出绑定世界、方块状态、库存版本和玩家状态。

| 字段 | 作用 |
| --- | --- |
| `blockStateId`、位置、维度 | 防止评估完成后换了方块或世界 |
| `toolCandidates` | 库存槽、物品/组件、耐久、采掘资格与估计速度 |
| `harvestEligible` | 是否满足该方块的工具要求，不等于保证某个随机掉落 |
| `expectedDropMode` | 普通、精准采集、时运或未知规则 |
| `estimatedTicks`、`estimateQuality` | 估计耗时与可靠程度 |
| `hazards` | 落沙、流体、自身支撑、上方坍塌、附近危险 |
| `unmet` | 缺工具、等级不足、不可破坏、背包满或数据不可用 |

本机 1.21.1 已核对 `ItemStack.isCorrectToolForDrops(BlockState)` 与 `getDestroySpeed`。选定工具后，再用 `Player.hasCorrectToolForDrops` 和 `BlockState.getDestroyProgress` 核对实际玩家条件。

候选评估不应通过临时切换真实快捷栏来“试算”。先使用物品组件和规则估计，正式选定并装备后做最终核对。水下、悬空、挖掘疲劳、急迫和属性变化都可能使估计变化。

工具“能挖”与“能掉落”分开。清理一块泥土、采矿获取原矿、精准采集矿石，具有不同后条件。

## 4. 工具选择与执行

优先排除不能满足采集目标、耐久不足、属于保留装备或会产生不允许副作用的候选。剩余候选比较预计耗时、耐久成本、期望产物价值和换工具成本。

建议提供 `fastest / conserve / specified` 三种明确策略。普通采集默认 `conserve`，在满足资格的前提下避免消耗珍贵附魔工具。紧急开路可由已授权上层策略选择 `fastest`。

耐久按待挖数量和储备估算。耐久附魔的随机减耗只能作为期望，不能当成保证。工具可能在关键破块前损坏时，先换备用工具或返回 `tool_durability_low`。

状态机为：评估 → 选择 → 装备并核对 → 固定瞄准 → 生存破坏 → 破坏事实核对 → 拾取 → 所得核对。任一步状态变化后重新评估相关部分。

有进度但较慢的挖掘按预计时间和总预算处理，不能统一十秒后重来。没有进度、目标改变或失去可达性时停止。本次取消调用模组停止挖掘，并由执行令牌拒绝迟到的继续破坏。

## 5. 三条调用路径如何复用

`game_break` 默认保持“清除指定方块”的语义，可带工具策略与是否要求产物。`game_collect` 必须满足所需产物，不能用方块消失当作收集完成。地形 `canDig` 只负责已授权范围内开路，并把工具成本纳入路线。

由一个采掘业务模块拥有评估、装备和破坏周期。三个调用方传入不同目的与许可，不复制三套快捷栏选择和破块轮询。

路线规划可以读取估计采掘代价，但最终动作前必须用实际状态再核对。缺镐时不能先把石墙当作可低成本破坏，再在执行时反复失败。

## 6. 掉落与拾取归属

每次采掘有 `breakId`，关联命令、玩家 UUID、维度、方块位置、原状态和开始 tick。分别记录破坏事实、产生掉落、拾取数量与库存变化。

Fabric 的破块事件可以提供行为事实，但事件回调本身不保证列出本次全部掉落实体。需核对本版本事件顺序，再决定是否补充极小的掉落生成与拾取钩子。[1.21.1 事件文档](https://docs.fabricmc.net/1.21.1/develop/events)

精确方案在服务端破坏事务内，将实际生成的 ItemEntity 与 `breakId` 关联。对命令只匹配本人、同位置、同状态和有界窗口，不把邻近玩家的破块认领过来。

掉落实体可能合并、拆分、被别人捡走或随区块卸载。归属需维护来源数量账本，并处理实体 ID 转换。混合不同来源的堆叠被部分拾取时，不能仅凭一个 UUID 声称精确归属。无法确定时返回可证明的数量下界与模糊部分。

缺少服务端证据时，库存差只能标为间接证据。附近别人扔入的物品不记为“本次挖到”。经验单独统计，不能混入物品数量。

## 7. 工具升级流程

工具升级由 MC-2 提供可追溯的配方候选，实际配方和工位由当前服务器核对。第一版覆盖木镐 → 石镐 → 铁镐的有限前置链，复用现有背包、工作台、熔炉和领取动作。

升级计划有明确预算：所需材料、工位、燃料、预计时间、保留工具和停止条件。每次只解决一个缺失前置，不递归扩展无限的“先做更好的工具”。

`game_collect` 遇到缺工具时默认返回结构化前置条件。只有调用者显式允许前置制作，才按技能流程进行。工具准备是任务内有限流程，不依赖尚未实现的长期目标系统。

钻石、下界合金、附魔、修补和复杂模组工具在后续阶段扩展，使用同一资格和经济契约。未知配方不得靠字符串猜测。

## 8. 批次与需主流程采集

| 批次 | 交付 | 场景 |
| --- | --- | --- |
| CD-M1 | 资格、选择、耐久、三入口复用 | 石、矿、木、作物、无工具、错误等级、主背包工具 |
| CD-M2 | 破坏与掉落证据、拾取归属 | 他人同时挖、他人扔物、实体合并、背包满、掉落凹洞 |
| CD-M3 | 有限工具升级与路线采掘成本 | 从基础材料升级至石/铁工具，再完成指定采集 |

每个基础场景至少 10 次。记录评估工具、实际工具、破坏耗时、耐久变化、产物与证据等级。附魔、水下、疲劳和模组工具分别分组。

关键完成门：不能掉落所需产物的工具在开挖前被拒绝，工具不会在关键动作前意外耗尽，取消后不继续破坏，别人提供的物品不误报为本次产出。

数据不可用时保留明确失败或显式的单块手动破坏，不静默降低采掘要求。升级链失败时保留已取得材料与已制作工具，回执列明完成部分和缺失前置。
