# 鞘翅三维航路、轨迹控制与降落

日期：2026-09-14。状态：设计。依赖：[CD-0](./capability-deepening-plan.md)。单程导航先通过，再支撑 [跟飞](./air-follow-design.md)。

## 1. 现状与剩余问题

当前 `elytra.ts` 已补横向走廊筛选、两层扫描、烟花换槽、耐久刷新、附近落点和一次复飞。晚间真机记录证明塔至庭院和低补给早降成立。

但驾驶仍主要朝目标调 yaw/pitch，遇障提高巡航高度。没有侧向三维路线，也没有按当前惯性核对未来能否转过去。目标坐标同时承担巡航方向和着陆位置，难以复用于跟飞。

本轮另核对到以下边界：

- `shouldStop() && !landing` 仍使进近中的取消无法直接改变内部状态。
- 进近超时位于“距离没有改善”的 `else if`。持续微小改善时，截止时间不生效。
- “一次复飞”把 `landing` 设为 false，下一轮在 80 格范围内又可立刻进入进近，尚未定义完整的复飞轨迹。
- `chooseLandingTarget` 只沿当前航向查 24 格，每列下探深度等于前进距离。高于地面超过 24 格时，可能找不到脚下大片平地。
- 未找到落点时返回同高度的未核实坐标。`safeGroundBelow` 将非空气、非液体当支撑，未核对形状与危险方块。
- 停止滑翔即退出循环，尚未独立核对是否真正着地、落水或状态缺失。

源码：[elytra.ts](../../apps/stage-tamagotchi/src/main/services/airi/game-host/movement/elytra.ts)、[host-port.ts](../../apps/stage-tamagotchi/src/main/services/airi/game-host/movement/host-port.ts)。这些是代码证据，本轮未重跑飞行。

## 2. 方案选择

| 方案 | 能力 | 局限 | 决定 |
| --- | --- | --- | --- |
| 朝目标转向，遇障爬升 | 开阔场景简单 | 低顶棚、侧绕、惯性和落地难处理 | 保留为已知开阔场景基线 |
| 三维 A* 路点 + 当前转向器 | 能选绕行方向 | 可通行折线未必能飞，转弯能力未进入控制 | 只作粗规划层 |
| 三维走廊 + 有限候选滚动轨迹 | 同时考虑路线、速度、碰撞和资源 | 需要物理模型校准与计算预算 | 选定 |

不要求第一版实现完整连续优化求解器。先使用数量有界的控制原语和短时轨迹搜索，保留已经可行的下一段作为超时后备。

## 3. 职责与会话

主进程拥有目的地、总体预算、粗航路与候选落点。客户端模组拥有短时世界快照、轨迹预测、逐 tick 输入与安全反射。MCP 下发有版本的走廊和意图，返回批量状态，不承担最后几个 tick 的避撞。

`runElytraMove` 逐步收敛为主进程编排。新的飞行状态与物理决策放在模组的独立业务模块，避免继续扩大通用 `BotController`。后者保留统一输入仲裁。

| 契约 | 主要内容 |
| --- | --- |
| `FlightIntent` | 会话身份、修订号、类型 `transit / track / land`、目标区域、期限、补给预算 |
| `FlightObservation` | tick、位置、速度、yaw/pitch、姿态碰撞盒、健康、装备、当前烟花推进剩余状态 |
| `FlightCorridor` | 三维可行区域序列、入口与出口、地图版本、未知边界、允许速度范围 |
| `LandingSite` | 支撑区域、进入方向、接地高度、净空、粗糙度、已核对时刻、可达成本 |
| `FlightStatus` | 阶段、正在执行的轨迹 ID、偏差、预算、备选落点、退出原因 |

同一会话只允许一个控制器。`track` 更新不能触发 `land`。新意图不重做装备或起飞，除非状态机确实回到地面准备阶段。

## 4. 三维粗路线

以已加载区块构建多分辨率自由空间。粗单元可从 4 格尺度开始，只要内部未知或被占用就继续细分或标记不可用于确定性通行。

区域边界以有净空的入口连接。粗搜索代价包含长度、净空、爬升、预计烟花消耗、未知数据和到备用落点的偏离。拐角密集区域提高代价。

粗路线输出走廊，而不是要求飞行器逐一命中格子中心。通过门洞、峡谷和下界顶棚时，需要足够大的转弯空间。粗 A* 找到路径后，局部轨迹层仍可以拒绝“几何可通、当前速度不可飞”的路线。

未加载区域作为未知前沿。沿可停靠或可折返的安全走廊接近，获取新地形后扩展路线。知道服务端目标位置不构成中途地形可通行的证据。

侧绕、爬升、沿谷地和改换落点均为候选。禁止把爬升作为全部障碍的统一恢复动作。

## 5. 局部物理预测

定义无副作用的单 tick 转移 `stateNext = stepFlight(profile, state, input, world)`。状态至少包含位置、速度、朝向、滑翔姿态和当前火箭推进状态。模型不得通过移动真实玩家来试候选。

物理档案绑定 MC 版本、已知影响运动的模组组合与档案版本。1.21.1 以本机映射后的 `LivingEntity` 滑翔分支、烟花附着推进和碰撞流程为依据。逐项核对更新顺序和单位，不套用现实世界飞机模型。

Prismarine 的实现包含滑翔、烟花和碰撞逻辑，可作为阅读与离线对照来源。它不是当前 Fabric 实例的版本正确性保证。[项目源码](https://raw.githubusercontent.com/PrismarineJS/prismarine-physics/master/index.js)

### 候选生成与选择

候选由有限 yaw 变化、pitch 变化、是否使用烟花组成。初版可从 5 个转向 × 3 个俯仰 × 2 个推进选择开始。变化必须受当前速度与朝向变化率限制。

每条候选预测约 20–40 tick。只执行首个 1–2 tick，然后用新观测重新计算。必要时用少量分支保留下一阶段选择，数量与 CPU 时间均设上限。

先拒绝碰撞、未知空间、失效地图、违反高度/维度边界、补给不足和无法维持安全后备的候选。其余候选再比较走廊推进、离走廊距离、输入变化、速度误差和资源消耗。

权重不能让“更接近目标”抵消一次预测碰撞。安全条件与偏好代价分开。所有候选失败时进入明确的恢复或降落状态。

### 碰撞与误差

对每 tick 的移动段做连续扫掠，不能只测起终点。使用当前滑翔姿态的碰撞盒，沿预测轨迹与原版 VoxelShape 求交。射线读取、粗包围盒读取和实际碰撞核对是不同操作。

地图可按较宽区域批量读取，但碰撞只针对候选轨迹。读取返回覆盖掩码、截断与版本。整个读取失败或缺失某格都不能视为空气。

预测位置误差、目标误差与网络年龄扩大扫掠边界。扩大的边界大于走廊余量时，降速、缩短执行段或更换路线。没有实测校准前，不声称严格误差上界。

## 6. 起飞、进近与复飞

起飞点由地面路径可达性、前方净空、起飞落差、部署时间和起飞后走廊共同决定。普通平地无可行起飞方式时返回 `launch_unavailable`。本阶段不隐含建塔或摔落尝试。

进近先选支撑区域，再选择进入方向和所需速度。根据剩余高度与速度判断能否按计划接地。若不能，提前进入复飞，不等到已经越过落点才扭头。

状态机使用 `Prepare → Launch → Cruise → Approach → Flare → Touchdown → Terminated`。`GoAround` 与 `EmergencyLanding` 为独立状态，拥有自己的截止时间和目标。

复飞轨迹至少包含恢复高度、离开进近区和重新对准三个阶段。阶段完成前禁止重新进入 Approach。默认最多一次完整复飞，实际允许次数还受烟花和耐久储备限制。

着地须同时满足新鲜 `onGround`、合理接地位置和足够低的残余速度。落水单列结局。若需要步行补齐，明确切换到地形执行器，不能直接朝目标按前进。

## 7. 应急落点与取消

航程中持续维护少量候选落点，避免危险发生后才串行进行数百次方块读取。候选覆盖前方和可转向侧方，并以自身滑翔可达性筛选。

落点核对支撑面积、净空、危险标签、当前速度下的进入方向和停靠空间。花、火、细柱或仅有一个非空气格不构成有效落点。水面可以作为独立应急策略，不能混同普通地面着陆。

取消在所有阶段立即改变业务原因。保留当前输入片段所需的最小安全收尾后，由唯一安全控制者降落。原目标、旧跟随更新和新普通写命令不能抢占该收尾。

没有落点时输出 `no_reachable_landing`，同时执行有界的最小风险候选。若没有任何已核对候选，只能报告条件受限并触发既有反射策略。不能把未核实的同高度坐标记成安全落点。

各阶段截止时间在循环顶部独立判断。总清理期限不因“仍在改善距离”而延长。硬截止到达时，客户端收敛输入所有权，回执区分落地成功与收尾未核实。

## 8. 计算与资源预算

| 项目 | 首轮建议，待测定 |
| --- | --- |
| 本地控制 | 按游戏 tick 执行，轨迹更新每 1–2 tick |
| 粗路线 | 约 1–2 Hz，或地图/目标变化时触发 |
| 预测窗口 | 20–40 tick，速度提高时扩大地形前视 |
| 模拟预算 | 同时限制模拟步数和耗时，先以每次约 2 ms 为性能目标 |
| 主进程状态摘要 | 约 5 Hz，轨迹批量导出 |
| 备用资源 | 按到最近可达落点的预计消耗加余量，不能只固定留三发 |

超过计算预算时使用仍有效的已核对轨迹短前缀，随后减速或降落。不能阻塞客户端 tick 等网络数据。火箭使用按操作 ID 记录实耗，统计其持续推进，避免每个预测 tick 都重复计费。

## 9. 分批交付与需主流程采集

| 批次 | 内容 | 完成门 |
| --- | --- | --- |
| CD-E0 | 进近取消、独立期限、真实着地、旧任务隔离、明确未知 | 停止和异常场景有界收敛 |
| CD-E1 | 版本物理档案、输入驱动离线模拟、轨迹记录 | 10/20/40 tick 预测残差可量化 |
| CD-E2 | 三维走廊与有限候选控制 | 能侧绕山体、处理低顶棚和惯性转弯 |
| CD-E3 | 起飞候选、进近剖面、完整复飞、备用落点 | 约定测试场地的单程闭环通过，保留适用条件 |

主流程先采集无障碍滑翔、不同 pitch、转向、火箭推进和速度衰减。随后加入薄墙、低顶棚、斜向通道、山脊和突然出现的障碍。每类至少 20 次，保留失败轨迹与地图。

预测残差按版本、速度、姿态和地形分组。碰撞膨胀余量至少覆盖已测残差与观测延迟，超出已测范围时不自动推广结论。

单程场景核对到达率、实际航程、最大转角、烟花消耗、最低健康、落点误差和收尾耗时。取消、读取失败、耐久下降、多组烟花、无落点与旧修订重放单独验收。

未通过的物理档案只提供观察建议，不执行自主避障或跟飞。开阔场地的已有模式可作为显式受限能力，不能在复杂地形中静默回退。
