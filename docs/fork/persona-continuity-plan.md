## 1. 目标与基线

目标：跨会话、任务、模型切换和重启后，保持可辨认的身份与有来源的共同经历。
工作状态和社交状态可以有不同表达方式，但采用同一组有效身份与关系事实。

角色卡、character store、memory、情绪信号和 appearance/changed 已提供基础。
现有机制不能单独证明长期人格连续性。core-character 的空入口也不构成新增大型人格引擎的理由。
本计划先核对数据和提示词所有权，再接有界的连续性投影。

## 3. 状态划分与入口

以下是拟落实的责任划分。本批把记忆所有权补成现有 schema 上的最小契约，不新增人格引擎。

| 状态 | 首选现有所有者 | 更新与有效性 |
| --- | --- | --- |
| 稳定身份与人格约束 | 角色卡及其现有持久化 | 用户明确编辑；普通对话不自动改写 |
| 用户偏好与关系事实 | memory-core、memory store | 抽取和修订经既有审阅，有主体、范围与来源 |
| 共同经历 | journal 的事实引用与 memory 的有效摘要 | 已发生事件可作为来源，生成摘要仍需核对 |
| 短时情绪 | character/memory 现有 mood 状态 | 明确时效与重启策略，不自动晋升永久人格 |
| 当前意图和工作状态 | Flow、Plan、TaskRun | 运行时事实，任务结束后不保留为当前意图 |

本批的记忆作用域为 `MemoryScope = { userId, characterId }`。聊天记忆、任务完成事件、
角色反应和审阅后技能肌肉记忆都由运行时提供该作用域；普通抽取不能从模型文本推断作用域。
带作用域的行为检索必须同时匹配用户和角色。旧的无作用域记录仍可在审阅列表中查看，
但不能进入行为 prompt。会话已经持有 `userId` 与 `characterId`，因此不新增会话 schema。

共同经历使用已有的事实、`sourceContext`、事件 ID/类型、episodic 字段、审阅状态和事实状态表达。
当前意图继续由 Flow、Plan、TaskRun 提供；人格连续性 prompt 只提供角色卡规则、当前
作用域和少量模式边界，不复制完整任务日志。

代码入口：packages/stage-ui/src/stores/character/、stores/modules/memory.ts、stores/chat.ts。
来源契约入口：packages/core-agent/src/journal/types.ts 与 packages/memory-core/src/types.ts。
角色卡具体存储与选卡入口在 PC-0 追踪，不能只从一个 prompt 字符串反推所有权。

不变量：旧记忆不能压过当前指令和工具证据。模型自述不能直接修改身份。
角色与用户的主体关联必须可辨；A 角色的关系经历不能静默成为 B 角色的经历。
不以依赖感、占有欲或用户回复频率作为关系升级指标。

## 4. 实施批次

### PC-0：连续性数据盘点与契约

前置：DR-0；涉及事实行为前须有 MQ-2。

1. 追踪选卡、身份 prompt、social/work/btw 提示词与 mood 的真实读写链。
2. 列出每种状态的写入者、持久化位置、作用域和重启行为。
3. 明确角色标识、用户主体、会话与工作区之间的隔离规则。
4. 用现有事实模型表达可变信息，只为不能表达的稳定责任增加契约。
5. 为“换会话不换身份”“换角色不串经历”“工作结束清除当前意图”建立基线场景。

验收：任一身份或关系陈述都能找到来源与更新入口；没有多个 watcher 互相修复同一状态。
无法确定的产品政策记录为具体问题，不先用模型生成值填补。

### PC-1：有来源的共同经历

前置：PC-0、MQ-2；来源持久化通过 DR-3。

1. 从真实对话、已验证任务结果和外观事件生成小规模经历候选。
2. 记录参与主体、发生时间、来源事件、结果与有效性；优先复用已有字段和引用。
3. 将“她提出了一个想法”和“她执行了这个动作”分别表达。
4. 对来源缺失、被纠正、删除或过期的经历，停止主动使用并保留可解释状态。
5. 提供查看与修订入口，复用记忆审阅界面，不另设全套关系数据库。

验收：经历可追溯到真实事件；重复摘要不制造新经历；模型无法把 dreaming idea 写成已发生事实。
本批不保存原始镜像帧。图像长期保存只在 SP-5 与 MD-1 的规则确定后扩展。

### PC-2：统一而有界的连续性投影

前置：PC-1；与 MQ 的候选有效性规则保持一致。

1. 为当前角色选择稳定身份、少量相关偏好和近期共同经历，设置明确预算。
2. 将常变经历与当前意图放到适合更新的上下文位置，避免每条事件重写完整稳定前缀。
3. social、work、btw 和社交考量各取需要的投影，不复制整套工具或任务日志。
4. 用户改口后，下轮读取新事实；已完成任务不再以“正在做”出现。
5. 为模式切换保留表达语气与称呼习惯，同时保持工作证据和权限边界。

验收：跨模式陈述的事实不矛盾；上下文长度有界；远端快照不会触发事实回写或重复抽取。
具体预算先记录基线并设保守上限，不能以填满模型窗口作为目标。

### PC-3：跨天与模式切换行为验收

前置：PC-2、DR-3；主动表达部分使用已通过的 SP-0。

1. 用固定问题集覆盖初次交谈、旧经历回顾、用户纠正、换角色和切换工作状态。
2. 在新会话与重启后重复场景，核对来源事实和当前意图。
3. 对同一事实使用不同问法，区分事实连续性和措辞一致性。
4. 模型切换时先检验事实和规则保持，再记录表达风格差异。
5. 对“未发生但听起来合理的经历”设置反例，要求不声称亲历。

验收：可机械检查的事实正确；自然感由用户评价。不要把相同措辞或固定人设标签当作人格连续性的唯一标准。

### PC-4：关系体验观察与可回退调整

前置：PC-3；与 MD-4 的 30 天记录合并。

1. 记录用户纠正、经历混淆、重复话题、错误自述和模式切换的不适感。
2. 每次只调整一个表达或投影策略，保存前后版本与观察结果。
3. 将真实失败样本交回 MQ、SP 或 DR，不用扩写角色卡掩盖数据问题。
4. 验证导出恢复后主体隔离、有效经历和身份配置保持一致。

验收：形成带样本的体验报告，说明哪些变化有效、哪些撤回，以及未覆盖的角色和模型。
