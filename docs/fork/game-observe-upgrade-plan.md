## 1. 本轮确认的范围

用户已确认以下选择：

1. **允许服务端辅助观测。** 输出必须标明来源、遮挡证据和未知状态。服务端查到实体，不等于她亲眼看见实体。
2. **watch 在显式登记后持续运行。** 重要变化可以主动唤醒 AIRI，无需等待下一条玩家消息。
3. **唤醒后允许自主选择并执行游戏动作。** 本计划包含最小任务调度、运行权申请、中断和结果核对。
4. **观察能力优先交付。** 鞘翅地面起飞保留为独立批次，单独接入与验收。

此前确认的村民交易表方案继续有效：允许通过"打开菜单 → 读取交易表 → 关闭菜单"取得信息。该过程属于有副作用的领域动作，不放进普通观察。

OV-3 只实现"重要变化触发一次有界回应"。个人项目、长期目标、连续探索与跨会话恢复仍归 free-play。

## 2. 背景与现状核查

当前 `game_observe` 主要返回自身、背包、装备和状态效果。她缺少判断周围有什么、目标正在发生什么变化，以及下一步是否值得行动的信息。

两个典型场景：

- **村民交易**：无法方便地发现、选择和了解附近村民。
- **鞘翅**：运行中的起飞流程依赖跑出边缘。平地上持续等待离地，最终报告无法起飞。

2026-09-16 代码核查结果如下。

| 部分 | 当前实际行为 | 对本计划的影响 |
| --- | --- | --- |
| observe 聚合 | 读取自身、背包、装备、效果；额外读取的方块区域未消费 | 必须修复无效读取，并明确实际覆盖范围 |
| 微观方块 | 当前区域是 5×3×5，不是 5×5×5 | 不能据此声称覆盖前方三格或更远地形 |
| radius | 当前主要回显为 `observedRadius` | 参数回显不能证明完成了对应范围的观察 |
| entities.query | 返回基础身份、位置、距离和生命值；默认最多 100 条 | 当前查询结果没有 motion 与 sourceTick，必须补接口 |
| entities.get | `addExtra` 提供运动、姿态、存活状态及 sourceTick | 可复用字段语义，但不能误认为 query 已有这些字段 |
| 查询中心 | entities.query 未传 center 时使用世界出生点 | 宿主必须显式传自身坐标与维度 |
| vision.describeScene | `lookingAt` 已读取 `mc.hitResult`；射线网格采用步进近似 | 准星命中来源已经是游戏自身结果，需要补字段 |
| menu.snapshot | 当前没有完整 Merchant offers | 交易表读取明确需要 Java 增补 |
| CD-L 追踪 | 已有状态策略、限频门和轨迹历史；这些模块不会自行采样 | watch 仍需调度器、订阅生命周期和读取协调 |
| 事件轮询 | 常驻轮询依赖 `chatCommands.enabled`，并过滤为 chat | watch 不能直接依赖现有聊天轮询启动 |
| 能力发现 | 主要读取客户端 MCP 工具列表，服务端随后连接 | 工具名称存在，不证明对应后端可用 |
| 鞘翅起飞 | `runVehicleMove` 调用 `runElytraMove`，后者执行跑出边缘流程 | 修改 lifecycle 辅助函数不足以改变实际起飞行为 |

## 3. 设计原则与共同契约

### 3.1 观察、判断和执行分开

系统分为三层：

1. **观察层**：提供有来源、时间和覆盖范围的事实。
2. **判断层**：判断变化是否值得关注，由模型选择回应。
3. **执行层**：核对条件、申请运行权、提交已有领域命令并核对结果。

`game_observe` 本身不发送移动、攻击、使用物品或菜单输入。

watch 参数可以修改宿主内存中的订阅状态。订阅产生的自主动作通过独立运行记录提交，不能隐藏在一次 observe 的执行过程中。

### 3.2 服务端信息与亲眼所见分开

实体条目至少区分：

- 数据来源：客户端实体、服务端查询或其他明确来源。
- 客户端是否已加载该实体。
- 视线与遮挡检查结果。
- 这些检查发生的时间。

未进行检查时返回 `unknown`。不能因为服务端查询成功，就填成"可见"或"无遮挡"。

遮挡检查结果必须说明方法。例如，方块碰撞射线只能证明对应射线是否被方块阻挡，不能直接等同于整个实体在屏幕上可见。

对模型的表述遵循证据：

- 可以说："服务端雷达显示，墙后附近有一只僵尸。"
- 只有具备相应客户端证据，才可以说："我看见前面有一只僵尸。"

### 3.3 来源、时间与空间绑定

各层复用 CD-0 的观测契约，携带：

- source
- worldId
- dimension
- connectionGeneration
- 来源提供时的 sourceTick
- 宿主请求时间窗与接收时间
- 覆盖范围、完整性及缺失原因

客户端 tick、服务端 tick 与宿主时间不能直接相减。跨来源比较使用时钟映射与误差界。

来源没有提供 tick 时，保留宿主请求窗，并标明来源时刻未知。不能拿其他 RPC 的 tick 代填。

坐标统一使用世界坐标。运动向量使用格/tick。若展示格/秒，必须注明按标称 20 TPS 换算，不能当作服务器卡顿时的实际墙钟速度。

观察过程中发生换世界、换维度或连接代次变化时，丢弃旧绑定的响应。不能把两次连接的数据拼成一次当前观察。

### 3.4 能力缺席与读取失败分开

能力判断必须同时考虑：

1. 请求实际路由到哪个端点。
2. 该端点是否暴露所需工具与字段。
3. 对应客户端或服务端后端是否可用。
4. 返回数据是否属于当前世界与维度。

结构性缺席进入 `limitations`，例如接口不支持、所需后端未配置。

临时读取失败进入 `missing`，例如超时、后端暂时失联、数据格式错误。

暂时失联不能永久记为"不支持"。工具列表中有名称，也不能直接记为"能力就绪"。

### 3.5 输出预算与读取完整性分开

输出使用分层结构：

```
observed
  self
  environment
  crosshair
  radar
  blocks
  watch
  terrain
  limitations
  missing
  truncated
```

`finalSnapshot` 保留现有契约。背包、装备和效果纳入 self 层，不因重组而丢失。

必须分别记录：

- **上游截断**：数据源没有返回全部符合查询条件的对象。
- **输出裁剪**：宿主取得了对象，但没有全部交给模型。

某桶只在截断列表中出现 12 个对象时，只能称"本次读到 12 个"或"至少 12 个"。不能声称该范围总共只有 12 个。

默认文本预算初值为约 1,500 token，full 初值为约 3,000 token。预算包含元数据、缺失说明和关注集摘要，不包含图像。

裁剪优先保留：

1. 自身危险状态及关键限制。
2. 显式关注目标的重要变化。
3. 准星目标与近处相关实体。
4. 普通近场信息。
5. 远场条目与地形细节。

危险摘要、未知状态和截断标志不能因超预算消失。

## 4. 观察分层

| 层 | 内容 | 主要来源 |
| --- | --- | --- |
| L0 自身 | 位置、朝向、运动、生命、饥饿、氧气、模式、载具、背包、装备、效果 | 现有自身读取 |
| L1 环境 | 时间、全局天气、生物群系、局部降雨、光照 | 全局天气与客户端环境读取 |
| L2 准星与微观 | 游戏准星命中、方块状态、命中面与距离、脚下和附近碰撞信息 | vision.describeScene 与方块快照 |
| L3 实体雷达 | 身份、相对位置、运动、生命、类别、客户端与遮挡状态 | 服务端查询，按需补客户端证据 |
| L4 关注集 | 当前已知状态、变化、轨迹摘要、失联原因、订阅状态 | CD-L 策略与新增采样调度 |
| L5 宏观地形 | 表面高度采样、覆盖状态、粗略地貌摘要、可选画面 | 地形剖面与截图 |

L5 帮助她理解地貌。实际移动、起飞、落地和避障仍依赖相应执行器的局部碰撞与可达性检查。

## 5. OV-1：观测契约与基础聚合

原"零 Java 聚合"改为"基础聚合与必要字段增补"。本批包含实体查询的最小 Java 改动。

### OV-D1：输出与真实覆盖

统一修改宿主、共享契约、工具参数、渲染层投影和观察结果消费方。

- 将现有方块读取结果用于 blocks 层。
- 明确记录请求范围与实际完成的读取范围。
- 需要报告前方三格时，实际读取对应区域。
- 空气、无碰撞方块、未加载和读取失败保持区分。
- 非 air 列表只有在区域完整性已知时，才允许据缺席推断空气。
- 必需的自身绑定读取失败时，结束观察并报告原因。
- 其他层失败时，保留已成功读取的层。

`observedRadius` 不再仅回显请求参数。观察后置条件必须依据实际取得的数据，不能凭 radius 回显判断满足。

### OV-D2：雷达字段、排序与截断

宿主始终显式传入：

- 自身位置作为 center。
- 当前 dimension。
- 查询半径和 maxResults。

`entities.query` 增补：

- 批次来源与 sourceTick。
- 每实体运动向量。
- 可取得的存活状态。
- 后续村民富化所需的结构位置。

复用 `entities.get` 的字段语义与序列化逻辑。不能为全部雷达条目逐个发起 entities.get，制造 N 次补读。

雷达默认半径 32 格，上限 64 格。第一版查询上限显式设为 100，并保留 total、returned 和查询条件。

默认输出最多 16 个详细实体。各桶设置上限，玩家和村民也受预算约束，不承诺全部展开。显式关注目标和当前相关威胁优先。

必要的分类查询可以补充被普通查询挤出的目标，但必须：

- 计入 RPC 预算。
- 保留各自覆盖范围和截断信息。
- 按 UUID 去重。
- 不把重叠查询的计数直接相加。

排序使用相关性、距离和 UUID 作为稳定依据。类别不确定的实体进入 other，不能仅凭名称猜测敌意。

### OV-D3：准星复用现有游戏命中

`vision.describeScene.lookingAt` 已来自 `mc.hitResult`，不再称其为步进射线近似。

本批先消费现有准星字段，射线网格使用最小必要规模。`rayColumns` 与 `rayRows` 都必须显式控制。

下一批在现有接口上补充准星字段。只有性能测量证明需要独立轻量 RPC 时，才拆出专用接口。

射线网格继续单独标为近似观测，不能代替精确碰撞快照。

### OV-D4：全局天气与局部天气

本批接入 `world.getTimeAndWeather`。

全局下雨只写入全局天气。局部降雨尚不可取得时，返回明确的能力限制，不能默认填 false，也不能直接复制全局值。

### OV-D5：工具入口

默认只读白名单补入：

- `get_time_and_weather`
- `query_entities`
- `describe_scene`

用户已有的显式配置继续按其配置处理。

领域观察的来源开关、端点就绪状态和原始工具白名单分别表达。不能仅修改原始工具白名单，就认为 game_observe 已取得对应能力。

### OV-D6：参数

目标参数：

```
game_observe({
  radius?,
  focus?,
  watch?,
  image?
})
```

focus 支持：

- `surroundings`：默认近场摘要。
- `combat`：关注目标、生命变化和相关威胁优先。
- `trade`：村民信息优先。
- `terrain`：地形信息优先。
- `full`：扩大文本预算，仍有上限。

combat 与 full 都不代表无限输出。

### 验收

| 场景 | 必须满足 |
| --- | --- |
| 玩家远离世界出生点 | 雷达围绕玩家，而非出生点 |
| 非主世界观察 | 所有空间读取维度正确 |
| 周围超过 100 个实体 | 上游截断与输出裁剪分别可见 |
| 关注目标被挤出普通列表 | 不误报死亡或目标不存在 |
| 任一可选 RPC 超时 | 其他成功层仍返回 |
| 工具存在但服务端后端不可用 | 返回实际不可用原因 |
| 请求 radius 大于完成范围 | 不凭参数回显宣称完整观察 |
| 默认复杂场景 | 输出在预算内，关键限制与危险摘要保留 |

## 6. OV-2：环境、准星、村民与地形增补

本批拆为 OV-2A 和 OV-2B，可以分别验收。

### OV-2A：本地环境与交互对象

#### OV-D7：客户端环境

新增 `player.getEnvironment`，返回：

- 当前维度与生物群系。
- 天空光、方块光。
- 全局天气。
- 局部降雨及采样位置。
- 客户端来源时间。

局部降雨采用游戏实际的 `isRainingAt` 语义，考虑群系、位置和遮蔽。

可复用 MovementHandlers 中激流条件检查的做法：分别检查脚部与身体顶部位置。输出保留检查位置，聚合的 `localRain` 表示这两处是否至少一处受到降雨。

局部降雨、浸水和其他湿润条件分别表达，不能合并成同一个布尔值。

验收覆盖雨天林地、沙漠、屋檐下和水中。

#### 准星字段增补

在 `vision.describeScene` 中补充：

- 方块坐标、状态、命中面与命中点。
- 实体 UUID、类型和可取得的生命信息。
- 眼睛到命中点的距离。
- 维度与客户端采样时间。

读取准星不移动视角。若需要改变朝向观察其他位置，该过程属于独立动作。

#### OV-D8：村民富化与交易表

雷达中的村民附带职业、等级和群系变体。交易表不放进雷达。

`game_inspect_trades` 是独立复合动作：

1. 固定目标 UUID，核对交互距离和当前菜单。
2. 通过既有控制会话与交互路径打开目标菜单。
3. 建立目标 UUID、菜单实例与 containerId 的关联。
4. 等待交易表同步完成。
5. 读取完整 offers。
6. 关闭本动作持有的菜单。
7. 核对关闭结果并返回收据。

当前 `menu.snapshot` 没有完整 offers，本批明确补齐 Java 读取。

"交易表还没同步"与"交易表为空"必须分开。不能通过 `menu.select_trade` 代替只读查询，因为选交易可能移动物品并发送操作。

菜单关闭需要在模组端核对预期菜单身份。只有宿主先读后关，仍可能在两次 RPC 之间误关用户新打开的菜单。

收据分别记录：

- 是否打开了目标菜单。
- 是否取得交易表。
- 交易表是否完整。
- 是否确认关闭。
- 超时、取消或菜单被替换的原因。

异常清理只处理本动作持有的菜单。已经取得 offers，但关闭未确认时，保留两个事实，不能把整个过程写成完全成功。

### OV-2B：宏观地形

#### OV-D9：地形剖面及用途边界

新增 `terrain.surfaceProfile`，显式传入中心、维度、范围和采样间距。

初始输出：

- 8 个方向的环带采样，距离取 4、8、16、32、64 格中不超过请求范围的部分。
- 9×9 高度网格，初始间距 4 格。
- 每个样本的覆盖状态与来源。

服务端可使用 `WORLD_SURFACE` 高度图取得列顶部信息，但必须明确：

- 结果可能是树冠、屋顶、水面或下界顶层。
- 它不表示玩家当前所在楼层。
- 它不证明该高度可以站立。
- 它不证明两列之间可以通过。
- 间隔四格的采样可能漏掉一格洞、窄沟和薄障碍。

高度图原始 Y 与可站立脚高必须使用不同字段。前者按原版高度图语义记录；后者只能由碰撞与支撑检查取得。

列样本使用独立状态：

| 状态 | 含义 |
| --- | --- |
| `measured` | 取得该列的有效高度样本 |
| `no_surface` | 在明确检查范围内确认没有表面 |
| `unloaded` | 对应区块未加载 |
| `truncated` | 本次预算没有覆盖该样本 |
| `read_failure` | 读取失败 |
| `unsupported` | 当前来源不支持该读取 |

这些是列样本状态，不直接套用 CD-0 的逐方块状态枚举。

无服务端来源时，第一版明确返回该层不可用。客户端降级扫描作为后续切片，不能在没有实现和验收的情况下承诺可用。

#### 宏观提示与局部安全判断

粗网格可以支持：

> 东北方向的已采样表面明显更低，可能存在山谷。

若要支持：

> 前方三格有四十格落差。

必须额外读取当前位置对应楼层、前方支撑、玩家身体通道和下方覆盖范围。读取不足时，只能报告已确认的距离区间或落差下界。

执行器不能直接使用高度图决定前进、跳跃、起飞或落地。局部碰撞检查仍归移动与飞行模块。

#### OV-D10：截图独立交付

OV-2 不依赖截图。图像通路由 OV-4 单独验证。

### 验收

- 准星对准方块、实体和空处，字段与实际命中一致。
- 村民职业和等级正确。
- offers 延迟到达时，不误报为空。
- 用户切换菜单时，清理不关闭新菜单。
- 高度图在树冠、屋顶、水面、洞穴、桥下和下界场景中不被误用为脚下地面。
- 未加载区块保持未知。
- 一格洞场景证明粗网格不能替代局部安全检查。
- 地形读取不为观察强制加载或生成远处区块。

## 7. OV-3：持续关注、主动唤醒与一次自主动作

OV-3 分为三个切片。只有采样、唤醒和动作结算全部接通，才算本批完成。

### OV-3A：订阅与采样

#### OV-D11：复用追踪策略，补齐运行生命周期

复用 CD-L 的：

- UUID 身份绑定。
- 细观测与粗定位切换策略。
- 查询限频、退避和迟滞。
- 轨迹历史与不确定度估计。
- 已有类型化读取结局。

新增宿主侧订阅管理和采样调度。现有 tracker、gate 和 history 是可组合模块，不是常驻采样服务。

watch 操作采用显式语义：

| 操作 | 行为 |
| --- | --- |
| `add` | 添加 UUID；已存在时更新该订阅 |
| `remove` | 移除指定 UUID |
| `replace` | 用指定集合替换当前关注集 |
| `clear` | 清空关注集 |

未传 watch 时，不改变已有订阅。普通 observe 不隐式续期。

初始工程参数：

- 最多 8 个关注目标。
- 默认订阅有效期 10 分钟，可显式续期。
- 普通后台采样约 1 Hz。
- 后台新增实体读取初始上限 8 次/秒。
- 每目标最多一个在途读取。
- 暂时失联后按已有退避策略降低读取频率。

这些是可配置初值，需要结合真机延迟和成本调整。

订阅结束条件包括取消、到期、断线、世界绑定失效和宿主销毁。连接恢复后不重放旧订阅。

玩家自身换维度时，第一版终止旧维度订阅，不自动跨维度搜索。

#### 读取协调

observe、watch、follow 和 combat 对同一目标的读取通过明确的共享边界协调。

共享键至少包含：

- 世界与连接代次。
- 数据来源和维度。
- 目标 UUID。
- 读取种类及所需字段。

可共享满足新鲜度要求的快照和在途请求。高频执行器不等待低频 watch 的下一拍，watch 也不额外复制执行器已有的读取。

现有 `createCoalescedReader` 只保存一个键的状态，不能直接当成多目标缓存。实施时必须处理不同键并发、旧请求晚到与失效后的写回问题。

取消订阅后，迟到响应不能恢复订阅或产生刺激。

#### 生命周期与等待预算

跟随命令的等待预算决定"本次命令何时结束"。watch 有效期决定"还要关注这个目标多久"。二者分开。

一次跟随因失联结束，不自动删除尚未到期的 watch。watch 仍可在预算内低频寻找同一 UUID。

同名新实体不能替代原目标。

#### 失联不等于死亡

| 证据 | 允许表达 |
| --- | --- |
| 权威玩家列表确认离线 | `target_offline` |
| 同 UUID 被确认在其他维度 | `target_dimension_changed` |
| 实体读取缺席，但原因不足 | 暂不可观测，原因保留 |
| 实体未进入截断列表 | `target_not_in_read` |
| RPC 超时或后端失联 | 读取失败 |
| 新鲜的 `alive: false` 或关联到同 UUID 的明确死亡事件 | 已确认死亡 |

离线、卸载和查询缺席不能投影为 dead。

死亡事件与采样结果按来源时间排序。旧死亡事件不能覆盖玩家重生后的新状态。

### OV-D12：当前状态与增量

返回的关注条目以"当前已知状态"为主体，并附加变化摘要。

- 状态包含最后观测时间、年龄和缺失字段。
- 历史位置不能伪装为当前位置。
- 位置、生命和运动变化可以作为增量。
- 跨来源计算必须考虑时间误差。
- 轨迹原始样本留在内部，模型默认只接收摘要。

现有 `TargetObservation` 不包含全部生命等富状态字段。实施时扩展所属领域的观测投影，不能假定复用该类型就已经拥有完整实体状态。

预算不足时，可以省略部分关注目标的详情，但必须返回被省略的 UUID 和原因。不能只返回增量，让消费方自行猜测基线。

### OV-3B：重要变化进入主动决策

#### 变化分类

普通坐标变化用于跟踪，不逐拍唤醒模型。

首批候选刺激包括：

- 关注目标显著掉血，或跨过低生命阈值。
- 已确认死亡。
- 玩家目标离线、换维度或重新出现。
- 目标开始或结束滑翔、乘坐载具。
- 目标进入或离开与当前活动有关的距离带。
- 明确关联到关注目标的攻击或危险事件。

距离带使用迟滞和连续采样确认，避免边界抖动。生命变化阈值、低生命比例和冷却时间属于可配置策略。

订阅建立后的第一份快照作为基线，不当成一次"变化"。

服务端位置变化可以触发考虑，但不能自动推导为"她看见了危险"或"目标需要救援"。

#### 事件消费

watch 所需事件路由独立于聊天开关。关闭 `chatCommands` 后，已启用的 watch 仍能工作。

各事件源分别持有游标，按来源和事件 ID 去重。事件环出现缺口时记录覆盖缺失，不能把"没有读到死亡事件"解释为目标仍存活。

事件轮询、状态采样和模型唤醒采用不同频率。

#### 唤醒出口

watch 产生结构化刺激，通过 TG 的刺激管道进入决策。

本批包含所需的 TG 最小接线，不等待整条 TG 或 free-play 全部完成。

现有 life-mode 对正常只读游戏结果不会唤醒模型。因此必须新增明确的刺激投影与入口，不能伪造玩家聊天、工具失败或异常收据来触发它。

职责分配：

- 主进程持有刺激队列、去重、预算和运行申请。
- leader 构造有界上下文并调用模型。
- 跨进程契约集中定义，使用 Eventa。
- 多窗口不能分别消费同一刺激并重复运行。

#### 防重复与预算

首批初值：

- 同一目标、同类变化合并为一个情节。
- 普通同类刺激冷却约 30 秒。
- 全局模型考虑间隔至少 10 秒。
- watch 主动考虑初始上限为每 10 分钟 12 次。
- 同时最多一个模型考虑，另保留一个可合并的待处理摘要。

危险升级可以跳过普通类别冷却，但仍受模型预算和运行所有权约束。实时保命继续由模组反射负责。

发言预算与模型调用预算分开，接入既有 life-mode/TG 预算。沉默仍计入已发生的模型成本。

预算耗尽时继续保存有界状态摘要，不累积无限模型任务。预算恢复后先检查事件是否过期。

### OV-3C：自主动作与最小调度

#### 模型选择契约

一次主动决策支持：

- 发言。
- 私记。
- 沉默。
- 提出一次游戏动作。

社交 `self_decide` 保持现有职责，不在社交考量回合直接开放游戏写工具。

游戏动作通过受限的领域选择契约返回，至少包含：

- 刺激引用。
- 动作目的。
- 已有领域命令及参数。
- 目标 UUID 或位置。
- 期限与停止条件。

复用领域命令的参数契约，不接受任意脚本、原始 MCP 写调用或模型自造的成功判据。

首批活动可以覆盖短程接近、离开危险区域、有限时跟随、补给和其他已通过对应验收的领域动作。每种动作受当前世界、活动范围、资源和能力配置约束。

一个动作可以调用已有的复合领域命令。本批不新增模型自行延长的任务链。

#### 一次运行的边界

初始限制：

- 每次决策最多启动一个领域写命令。
- 命令执行期限默认不超过 30 秒。
- 为取消和核对结果预留独立的有界收尾时间。
- 动作结束后不自动递归启动下一次模型回合。

确有新的重要外部变化时，可以进入下一次考虑。动作自身的位置变化、普通回执和私记不能形成"自己唤醒自己"的循环。

#### 运行权申请

运行流程：

```
刺激合并
  → 预算与新鲜度检查
  → 模型选择
  → 原子申请运行权
  → 刷新动作关键条件
  → 提交领域命令
  → 核对回执和实际结果
  → 释放运行权
```

运行权必须与用户任务、现有 Flow 和其他自主工作协调。

现有 game-host 单写门只解决游戏命令并发，不能代替应用层运行权。若现有运行申请入口不足，本批补齐共享申请与撤销边界，不能新增一个互不知情的"watch 锁"。

不能采用"先检查空闲，等待模型，再直接执行"的方式。模型返回后必须重新原子申请，并复查：

- 用户是否暂停。
- 世界和连接是否改变。
- 目标是否仍有效。
- 工具能力、物品和动作前提是否仍满足。
- 是否有其他任务取得运行权。

游戏命令继续通过现有 Flow/领域入口和 command-registry 提交，使用既有写锁、租约、控制会话和后置条件。

不要求先实现长期目标项目。一次 watch 活动可以不属于持久项目，但必须有独立的运行身份。

#### 中断规则

| 事件 | 处理 |
| --- | --- |
| 普通 watch 新变化 | 合并入待处理摘要，不反复重启当前动作 |
| 明确用户游戏任务 | 撤销自主运行，在确认释放控制后交给用户任务 |
| 用户停止自主活动 | 先阻止新派发，再取消当前自主命令；保持暂停，等待明确恢复 |
| 用户普通聊天 | 不自动解释为停止；按现有交互入口处理 |
| 模组反射接管 | 原命令按既有抢占契约结束；稳定后重新观察 |
| 目标失联或动作前提失效 | 按当前命令的有界失败和停止规则收尾 |
| 死亡、断线、世界或维度变化 | 撤销旧运行和旧绑定，不重放旧命令 |
| leader 更替 | 旧决策失效；主进程核对当前运行，不重复派发 |
| 取消作为动作来源的 watch | 取消该订阅派生且仍在运行的自主活动 |

用户任务的运行权不能被普通自主刺激抢走。紧急反射仍可按原有规则接管输入。

取消请求与停止确认分别记录。停止未确认时，不把旧运行当作已经安全释放，也不立即派发新的写命令。

#### 身份与迟到结果

至少关联：

- 刺激或情节 ID。
- watch 订阅版本。
- 自主运行 ID。
- 决策 ID。
- 游戏命令 ID。
- 世界与连接代次。
- 控制会话 ID。

迟到模型结果不能在用户停止后启动动作。迟到回执可以补全原运行的事实，但不能释放新运行的锁或触发下一次活动。

重复刺激与重复提交不能重复执行动作。

#### 配置与失败抑制

自主配置区分：

- 仅记录。
- 允许主动表达。
- 允许自主动作。

本轮交付第三种模式。社交静默与游戏暂停分别处理，关闭主动发言不等于停止已允许的游戏活动。

同一目标、目的和失败前提下的重复失败进入抑制。只有相关条件变化后才重新尝试，不能靠改写目的文本绕过限制。

### OV-3 验收

| 场景 | 必须满足 |
| --- | --- |
| 不调用 observe，目标持续移动 | 后台状态仍更新 |
| 两次 observe 之间目标掉血 | 第二次能取得变化，符合条件时产生刺激 |
| 目标普通匀速运动 | 不逐拍调用模型 |
| 同名实体替换 | 始终保持原 UUID |
| 离线、卸载、截断和死亡 | 四种事实不混淆 |
| 关闭聊天触发 | watch 仍按配置运行 |
| watch 与 follow 同时关注目标 | 共享有效读取，后台请求不翻倍 |
| 没有新玩家消息，出现重要变化 | 模型能选择并完成一次允许的自主动作 |
| 用户任务在模型思考时到达 | 自主动作不能随后抢占运行权 |
| 用户停止后模型结果晚到 | 不派发动作 |
| 旧取消回执晚于新任务开始 | 不释放或停止新任务 |
| 同一事件重复投递 | 最多产生一次对应动作 |
| 一次动作失败后环境不变 | 不无限重试 |
| 断线重连或 leader 更替 | 旧订阅、决策和命令不重放 |
| 安静模式 | 可以保持允许的游戏活动，同时不主动发言 |

调度与取消使用确定性测试核对。模型真机验收不要求每次选择相同回应，但必须分别覆盖沉默、表达和自主动作分支。

## 8. OV-4：截图通道

### OV-D13：显式请求与能力判断

`game_observe({ image: true })` 显式请求截图，默认关闭。

同连接截图间隔初值为 10 秒。图像预算、文本预算和后台采样预算分别记录。

无法取得截图或当前模型链路不支持图像时，返回明确原因，保留可用的结构化观察。

### OV-D14：验证图像确实进入模型输入

实施时逐段检查：

1. 模组返回截图。
2. MCP server 产生 image content。
3. game-host 保留图像内容类型。
4. Eventa 与渲染层工具结果保留图像语义。
5. provider 适配层把图像送入实际模型请求。

不能把以下情况记为"模型已看见截图"：

- base64 被序列化成普通文本。
- devtools 能显示图片。
- 模型只收到了"截图成功"的文字。

验收使用只能从画面取得、结构化观察未提供的信息，结合实际请求载荷核对图像输入。

若只能接通 devtools，则记录为部分完成，不宣称模型视觉通路通过。OV-4 不阻塞前面各批。

## 9. OV-5：鞘翅地面起飞宏

本批独立接入与验收，不作为观察能力交付的前置条件。

### OV-D15：模组按 tick 执行

新增 `movement.elytraLaunch`，复用跳跃任务的身份、状态查询、取消与截止时间机制。

建议状态：

```
prepare
  → jump
  → release-jump
  → deploy
  → boost
  → handoff
```

推进依据是真实状态：

- 装备与烟花已就绪。
- 已离地。
- 起跳按键已释放，可以产生下一次展开输入。
- 已确认 fallFlying。
- 烟花使用已发生。
- 已满足巡航接管条件。

不以"固定两三 tick 后必然可以点火"作为正确性条件。各阶段保留期限和类型化失败原因。

`launched` 只表示已确认达到交接状态。记录位置、速度、飞行状态、tick、烟花使用及失败原因。

### OV-D16：接入实际执行路径

必须同时处理：

1. `runVehicleMove('elytra')` → `runElytraMove` 的实际起飞分支。
2. 空中跟随的起飞评估与执行入口。
3. `flight/lifecycle.ts` 中的起飞候选和条件。
4. 起飞宏到巡航控制器的输入交接。

平地起飞和边缘起飞作为明确候选，根据地面可达性、净空、资源和后续飞行空间选择。

不能预设悬崖永远优于平地。

`probeLaunchSite` 与 `selectLaunchPoint` 的未知语义需要同步修正：未加载、未读取与确认没有地面分别表达。不能把 `surfaceAt === undefined` 直接解释为满足最小落差。

### OV-D17：控制与依赖

起飞宏使用既有 controlSessionId 和客户端 tick 租约，不另立输入通路。

交接期间：

- 起飞宏和巡航控制器不能同时写输入。
- 宿主不参与起跳、展开和点火之间的逐 tick 时序。
- 宏完成时保留最终状态。
- 巡航接管使用该状态并核对新鲜度。
- 旧阶段清理不能清除新阶段的输入。

装备、耐久、烟花储备、取消和安全降落仍沿用飞行领域规则。

本批不替代 CD-E 的完整驾驶、避障和落地验收，也不重复实现远距伴飞的经济策略。

### 验收

- 平地无坡起飞，交接巡航并完成降落。
- 可用的边缘起飞路径不回归。
- 低顶棚、前方障碍和未知区域得到明确处理。
- 无烟花、鞘翅不可用或耐久不足时原因正确。
- 每个阶段取消后有界收尾。
- 点火不因轮询重复提交。
- 单程飞行与空中跟随都实际调用新起飞路径。

## 10. OV-6：原移动障碍专题撤销

原"移动障碍真实高度与 game_jump"不再作为独立 OV 批次。

碰撞形状、跳跃规划与逐 tick 控制归 CD-G。已有通过证据不表示所有跑酷几何都已解决，未完成场景继续按验收清单记录。

`no_safe_takeoff` 等预测器拒绝，只能说明当前状态、模型和候选搜索范围没有找到可接受方案。不能单凭该结果宣布某种跳跃在原版中不可能。

非寻路场景出现明确需求前，不新增全局 `game_jump` 工具。

## 11. 实施顺序与完成门

| 顺序 | 批次 | 完成门 |
| --- | --- | --- |
| 1 | OV-1 | 数据来源、时间、维度、覆盖与截断正确；基本观察可用 |
| 2 | OV-2A | 局部环境、准星字段、村民富化与交易读取分别通过 |
| 3 | OV-3A | watch 订阅、后台采样、共享读取和生命周期通过 |

| 5 | OV-3C | 一次自主动作、用户优先、中断与结果核对通过 |

OV-3B/3C 是 TG 刺激出口和 free-play 一次活动的最小落地切片。后续 TG/free-play 复用本批的契约、运行权和生命周期，不再创建另一套调度。

本计划未覆盖的长期部分：

- 持久个人项目。
- 自动延续的多步骤游玩。
- 兴趣和偏好的长期更新。
- 跨会话恢复。
- 没有具体刺激时的自由探索心跳。
