## 范围

1. 缺口表新增三项：跟随飞行目标（鞘翅跟飞）、跟随的长距离定位回退、移动目标与重力弹道。
2. 能力缺口两项：挖矿与工具升级（P1）、船/马/矿车（P1）。

## 1. 跟随飞行目标（鞘翅跟飞）

- **现状**：`game_follow` 只跑地面地形腿（批 2 后为连续跟随）；鞘翅仅存在于 `game_move_to {vehicle:'elytra'}`（一次性：装备→起飞→巡航→进近→降落，落点校验）。目标超出 64 格或跨维度 → `target_lost`；连续 3 腿失败 → `target_unreachable`。
- **需要回答**：目标是否在滑翔如何可靠判定（客户端 `player.getState.fallFlying` vs 实体查询加字段）；跟飞应链式调用 elytra mover 还是给 follow 增加飞行模式；目标在空中时如何“不降落”地重设航点（现有 mover 的进近触发条件是水平距离阈值，与“跟随”语义冲突）；目标突然落地/升空/换维度时的收敛；火箭与耐久预算；停止所有权（StopScope 已有基础）。
- **已有线索**：复审 §6 的阶段表（起飞/巡航/局部控制/进近/紧急降落/结束）；Baritone 1.19.4 `ElytraProcess`（职责划分参考，含“找不到落点可能盘旋”的限制）；当前 `movement/elytra.ts`、`movement/vehicle.ts`、`index.ts` 的 follow 循环。
- **期望产出**：设计文档（模式与状态机、目标追踪契约、预算与安全策略、批次拆分、真机验收场景：直线跟飞/绕山跟飞/落地跟随/丢失与恢复）。

## 2. 跟随的长距离定位回退

- **现状（经本轮校正）**：follow 经 `query_entities` 查询，以她为中心传入 64 格半径；该工具属于服务端优先路由，双端点连接时并非客户端查询。64 格是本次调用限制。服务端玩家列表坐标（`game_locate`）已存在但未接入跟随，详见 [目标追踪设计](./target-tracking-design.md)。
- **需要回答**：超出半径后如何切换到服务端坐标（频率、延迟、权限）；目标在另一维度的处理（`target_lost` vs 结构化 `out_of_range`）；与飞行跟飞的复用边界（同一目标抽象的两种执行器）。
- **期望产出**：短设计（目标抽象 + 两级定位 + 切换与滞回 + 验收）。

## 3. 移动目标与重力弹道

- **现状**：R9 已做“每 tick 重读目标 + 按预计飞行时间的**线性**预判”（可配置开关）。重力/阻力未建模；不同投射物（箭/弩箭/三叉戟/雪球/药水）速度与阻力不同；高差与远距离精度未评估。
- **需要回答**：按目标版本的速度/阻力/重力做有界轨迹预测的模型与误差界；预判开关的默认值；与友军阻挡检测共用预测线；验收指标（命中率/脱靶距离）与真机方法（移动标靶）。
- **已有线索**：复审 §3.3、§8；`BotController` 的 `combatLeadEnabled`、`aimAtTarget`。

## 4. 挖矿与工具升级（P1 能力缺口）

- **现状**：`game_break` 是单块原语（生存挖掘 + 轮询确认），**不感知工具**：手持工具不当会非常慢甚至无掉落；采集（collect）也只按方块 id 搜索，无工具选择/耐久判断；掉落归属只按物品计数。
- **需要回答**：按方块选工具（材质/等级/附魔效率/时运）、采掘资格（缺工具时的类型化失败与前置条件）、耐久与经济（何时换备用工具）、掉落归属（本次破坏的掉落物身份）；与 `game_break`/`collect`/地形执行器 `canDig` 的复用边界。
- **期望产出**：设计文档 + 批次（工具选择表由数据驱动或由 MC-2 知识提供？）、验收（石/矿/木/作物/无工具五类）。

## 5. 船、马、矿车（P1 能力缺口）

- **现状**：短程执行器存在（MC-3b 的船/矿车/炽足兽基础），载具**取得**与完整路线不完整：马需驯服+装鞍，矿车需放置+起步，船需可行水路。
- **需要回答**：取得流程（放置/上船/驯服）与失败类型化；与 `move_to.vehicle` 的载具状态契约；水路/铁轨/道路的规划边界；真机验收场景。
- **期望产出**：设计文档 + 批次。

## 6. 鞘翅深度（复审 §6）

- **现状**：走廊扫描已修正（横向 1.5 格筛选、两层垂直、不可读保守）、进近独立期限、就近落点与一次复飞已做；但仍是“朝目标调 yaw/pitch + 遇障主要爬升”的浅控制，没有三维可通行走廊搜索，也没有按当前速度的候选轨迹核对。
- **需要回答**：三维走廊表示与搜索（粗网格/体素/航段）、局部候选轨迹（左右转角×俯仰×烟花使用）的代价与选择、转弯惯性、复飞/紧急降落策略的形式化、地形读取（宽）与碰撞判定（玩家体积沿轨迹扫过）的分离；飞行中断（死亡/断线/换维度）的收敛。
- **已有线索**：复审 §6 表与 §8 飞行场景组；相关代码 `elytra.ts`（扫描/进近/落点）、`host-port.ts`（视觉与地形读取能力）、Baritone `ElytraProcess`。
- **期望产出**：设计文档（航路与控制的职责边界、数据结构、批次与真机验收含轨迹记录方法）。
