# 目标追踪与长距离定位

日期：2026-09-14。状态：设计。依赖：[CD-0](./capability-deepening-plan.md)。服务于地面跟随、跟飞和远程瞄准，原始观测共用，各自预测策略分开。

## 1. 现状与问题

`game-host/index.ts` 的 `resolveFollowTarget` 和 `readFollowPositionByUuid` 每次以自身为中心查询 64 格，最多返回 100 项。跟随固定 UUID 是正确基础，但超出范围、返回截断、查询失败最终都可能表现为目标丢失。

需要纠正草稿：双端点下 `query_entities` 已优先走服务端。模组 `EntityHandlers` 在服务端世界中查询。64 格是查询限制，不能直接解释为客户端实体加载距离。

`game_locate` 已使用服务端 `players.list`，但上层回执只返回名字、位置和可选维度，未传递列表中已有的 UUID。`entities.get` 已能按 UUID 查已加载实体。当前实体描述缺少跟飞所需的 `fallFlying` 和观测时刻。

来源：[game-host/index.ts](../../apps/stage-tamagotchi/src/main/services/airi/game-host/index.ts) 1700–1765、2276、2442 行。模组：`handlers/EntityHandlers.java`、`PlayerAdminHandlers.java`、`support/Levels.java`。

## 2. 候选与决定

| 方案 | 收益 | 局限 | 决定 |
| --- | --- | --- | --- |
| 把 64 格改成更大半径 | 最快接线 | 返回截断、成本和维度问题仍在，非玩家未加载仍不可见 | 不作为完整方案 |
| 全程轮询玩家列表 | 玩家定位简单 | 无法精细控制非玩家，速度和姿态不足 | 作为低频定位来源 |
| UUID 单目标精细读 + 低频全局定位 | 减少枚举，能表达来源与精度 | 需补目标快照契约 | 选定 |

首次名字解析可以复用现有查询和玩家列表，随后只追踪 UUID。同名新实体不能自动替换旧目标。

## 3. 目标观测契约

| 字段 | 语义 |
| --- | --- |
| `targetUuid`、`entityType` | 固定身份，不按坐标或名字重新归属 |
| `worldId`、`dimension` | 坐标作用域，缺少时不进入精细驾驶 |
| `position`、`velocity`、`yaw`、`pitch`、`bounds` | 明确单位和来源。速度可缺失，不用零代替 |
| `onGround`、`fallFlying`、`riding`、`alive` | 三态事实：真、假、未观察 |
| `source` | 客户端已加载实体、服务端实体、服务端玩家定位或历史记录 |
| `sourceTick`、`receivedAt`、`requestDuration` | 按 CD-0 区分时钟，计算年龄与误差 |
| `visibility`、`completeness` | 已加载、范围外、列表截断、未加载、不可用 |
| `positionUncertainty` | 由采样年龄、网络延迟和运动变化得到的估计误差 |

不要把服务器坐标等同于本地可控制的目标。目标位于客户端未加载区域时，粗路线可以朝它移动，精细追踪仍需要本地地形和足够新的运动状态。

精细来源建议由模组按 UUID 读取客户端已加载实体，增加姿态、滑翔、骑乘和碰撞盒。服务端单目标读保留为另一种明确来源。来源切换记录原因，不混合成无标签的“当前位置”。

所有空间请求显式传维度，并核对响应。当前 `Levels.resolve` 缺省主世界，不能在跨维度跟随时沿用省略参数的调用。

## 4. 两级定位与切换

### 精细追踪

模组逐 tick 读取本地目标，驾驶器使用最新样本。主进程按约 5 Hz 获取摘要即可，不为每 tick 发 MCP 请求。移动目标的瞬时控制留在客户端。

服务端精细读只有在字段完整且时钟可映射时才提供速度预测。旧采样与乱序数据丢弃。任何来源都不能凭连续相同坐标判定玩家已经落地。

### 远处定位

玩家超出精细观测范围时，使用已有玩家列表或按 UUID 的玩家读获取位置和维度。建议每秒最多一次，多个消费者共享同一只读采样。失败时有界退避，查询未结束前不叠加同目标请求。

非玩家只使用服务器仍加载的实体或带年龄的最后观测。服务器没有加载实体时返回 `entity_unloaded`，不能承诺全世界寻回。

### 滞回与失联

首轮建议：精细数据连续 3 次缺失或年龄超过 0.5 秒，转入粗定位。恢复精细模式需至少两个递增的新样本，避免反复切换。高速或狭窄区域使用更短可接受年龄。

粗定位连续 3 秒无新鲜结果时转 `waiting_for_target`。默认等待预算建议 10 秒，并受整条命令期限限制。超限返回明确原因，不无限追逐最后坐标。

| 情况 | 输出 | 跟随动作 |
| --- | --- | --- |
| 精细样本暂缺，粗定位同维度 | `coarse` | 走向可达会合区域，不做贴身追踪 |
| 服务端明确离线 | `target_offline` | 结束或按有限等待策略处理 |
| 目标在另一维度 | `target_dimension_changed` | 终止本段，保留目标维度，不跨维度套用坐标 |
| 服务端读取无权限 | `locator_unavailable` | 保留近处追踪能力，不能假称目标离线 |
| 非玩家实体未加载 | `entity_unloaded` | 有限等待或结束，保留最后观测年龄 |

本阶段不新增跨维度传送、强加载或自动找传送门。后续传送门路线需独立定义连接关系。

## 5. 预测与消费者边界

追踪模块只提供观测历史和误差。地面跟随选择会合站位，跟飞选择滞后的目标轨迹，瞄准选择投射物抵达时的位置。三者不共用一个预测终点。

线性外推只在短窗口内有效。突变、传送、骑乘切换和落地事件会清掉速度滤波历史。超出窗口时扩大误差并降低控制强度，不能一直延长直线。

默认沿用当前服务器已有读取权限。若服务器不提供远处定位，则显式降级到已观察目标。目标跟随不依赖管理员传送或世界写权限。

## 6. 批次与验收

| 批次 | 实现 | 需主流程采集 |
| --- | --- | --- |
| CD-L1 | 单目标契约、UUID 接线、维度与年龄、乱序过滤 | 64 格边界、超过 100 实体、目标重名、主世界与下界同坐标 |
| CD-L2 | 低频全局定位、来源切换、有限等待 | 远离后返回、权限不足、服务端超时、目标离线 |
| CD-L3 | 客户端目标运动字段与轨迹摘要 | 起飞/落地、骑乘、瞬移、网络抖动 |

验收不只看能否追上。还要看 UUID 是否保持、使用了什么来源、数据有多旧、来源切换多少次、目标不同维度时是否还在发移动。

故障注入包括重复响应、旧响应晚到、坐标为零、状态缺失和 tick 重置。停止后采样订阅释放，迟到观测不能复活已结束的跟随命令。
