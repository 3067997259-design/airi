## 背景与主诉

现状中她唯一的世界唤醒通道是玩家消息：X-10 三级策略（管理员/黑名单/采样）把
一条 chat 转成对话回合，她才能借对话调用一次工具。事件流里的其他一切——她被
射一箭、被怪打残、被玩家 TP 到身边——不会产生任何模型调用，她不说话也不动。

[free-play 设计稿](./minecraft-free-play-design.md) §5.1/§6.2 已经假设
"事件驱动 + 低频心跳复查"，但事件源引擎与出口契约未定义。本文补这个缺口：
它是 free-play F0 的前置之一，同时独立交付一件更早可感的事——**被动场合的
自主对话**（"像 life-mode 那样"：不干活时也能对世界有反应）。

## 设计原则

- **刺激 ≠ 发言 ≠ 行动**。事件先成为"刺激记录"（可观察、可去重、可审计），
  再由两条独立出口消费：对话冲动（社交）与行动候选（free-play）。对话冲动
  永不直接执行工具（守 CONSIDERATION 边界：社交考量不推进工作）；行动候选
  必须走 free-play §5.3 的宿主核对与运行权申请。
- **不伪造信源**。刺激是游戏事件，不是玩家消息。由此产生的发言自带"我注意
  到"的来源标记，不注入 X-10 的玩家消息通道。
- **预算与频控一等公民**。沿 MC-1b 压缩与 free-play §6.2 额度纪律：所有模型
  调用计入可见预算；类别级冷却 + 全局频控；社交静默沿用现有配置（§6.3：
  社交静默 ≠ 游戏暂停）。
- **危险优先但不抢锁**。危险类刺激提高唤醒优先级，但不绕过游戏写锁与当前
  命令租约——刺激只能入候选/冲动，不能直接派发命令。即时保命永远是 mod 侧
  反射（MC-0d），不经模型；模型只做事后认知（"刚才差点死"）。
- **时间与身份纪律（2026-09-16）**：情节窗与新鲜度按 CD-0 三时钟域规则计算
  （事件盖服务端 tick 戳，判定走 `MappedTimestamp` 误差界，不直减毫秒）；
  "她自己在动"以控制会话状态为准，不做模糊推断；刺激记录带维度字段（CD
  D12：跨维度事件不混入当前世界上下文）。

## 刺激分类（首批）

| 类别 | 事件 | 来源 | 默认出口 |
|---|---|---|---|
| 危险 | `player_damage`（按 amount/healthBefore 分级）、`player_death`、`game:reflex` | 已有 SSE | 对话冲动 +（存活时）行动候选 |
| 社交 | `player_join`/`leave`、攻击归属到具体玩家、附近玩家聊天 | 已有 + TG-3 增补 | 对话冲动 |
| 位置异常 | TP 检测（跳变 + 无控制会话）、维度变化 | TG-3 新增 | 对话冲动 |
| 环境 | 天气/雷暴变化、群系变化、日出日落 | TG-3 新增 | 对话冲动（低开口率） |
| 进度 | 命令回执终结、反射结束、菜单超时 | 主进程内部 | 行动候选 |
| 空闲 | 心跳到期（复用 life-mode/long-goal 唤醒） | 主进程 | 行动候选（free-play） |

## 防刷屏与发言节奏

自主发言做砸的方式就是刷屏播报器。防刷屏不是把过滤器调严，而是让沉默成为
系统与模型的共同默认，分三层：

**一、物理去噪（刺激合并，未到模型）**

- 情节（episode）为合并单位：伤害事件间隔 <8s 归同一场，整场只产生一次
  冲动，输出聚合摘要（"10 秒内被僵尸打了 3 次掉 8 血"），不逐条转述。
  窗口判定按三时钟域规则加误差界（见设计原则）。
- `entity_death` 一律计数化（"附近死了 40 只怪"），除非涉及她本人、玩家或
  有名生物。`player_join/leave` 抖动合并（同一人窗口期内反复进出算一次）。
- 危险类是唯一实时例外：血量跌破阈值或出现新攻击者时立刻升级冲动，不等
  情节结束。被打残还等摘要窗口，比刷屏更不像人。

**二、认知显著度（习惯化）**

- 每个刺激算 salience = 相关性 × 幅度 × 新颖度；低于阈值只进刺激日志，
  不产生冲动，仅在她真开口时作为背景上下文出现。
- 新颖度随重复衰减：本会话第一场雨 1.0、第二场 0.5、第十场 0.1；雷暴算
  变体，分数回弹。远场/与她无关的事件 salience 直接趋零。

**三、社交预算（硬顶 + 间距 + 预算可见）**

- 硬性上限（初值）：每 30 分钟 ≤6 次自主发言，两次发言至少间隔 45s。
- 预算趋紧时按显著度丢弃：环境/社交类静默（记录在案），只放危险类。
- **剩余预算放进冲动上下文**：`self_decide` 本就支持开口/私记/沉默，让
  模型看到"这半小时已经说了不少"，它自己会选沉默——比机械截断自然。
- 环境与社交类冲动默认走低频"摘要心跳"批处理（几分钟一次 digest 覆盖
  多条刺激，一次冲动机会），不逐事件触发；危险类不受此限。

用户控制：安静模式（仅危险类可开口）、类别开关、发言量档位（低/中/高对应
不同上限），并入 free-play §6.3 自主配置；全局开关（回到只有玩家消息能唤醒）
保留。初值全部参数化，真机调。

## 批次划分

### TG-0 · 刺激管道（只记录）

- 主进程把 `events.getRecent` 轮询从 chat 专用扩成全类型路由：去抖（同源同类
  窗口期合并）、类别级冷却、相关性初筛（与她有关的 damage 才进；远场
  `entity_death` 降采样——沿用 X-10 sampled 思想）。
- 刺激记录存内存环形，绑定 `connectionGeneration`（断线清空，沿 M1-D2 语义），
  带维度字段；devtools 刺激流可见。情节窗与新鲜度按 CD-0 时钟映射计算。
- 不调用任何模型。验收：真机射一箭、打一下、TP 一次，刺激流出现对应记录且
  重复事件不重复入流；模型调用次数为零。

### TG-1 · 对话冲动出口

- 刺激 → 冲动卡片 → life-mode/CONSIDERATION 的 `self_decide` 链：开口、私记
  或沉默都合法。冲动以"情节/digest"为单位，不以单事件为单位；上下文带
  聚合摘要、剩余发言预算，以及带 CD 来源/新鲜度戳的观察摘要（"她当时看到
  什么"——引用 OV 线分层观察，防刷屏三层见上文）。
- 危险类带"呼痛/求助"倾向但不强制开口，且是唯一可实时（不等 digest）的
  类别；环境/社交类默认低开口率。桥能力缺席时（如 target-observation 不可
  用）危险归因降级为类型化限制，不静默缺数据。
- 验收：被打残时她**可能**说话（多次运行的分布，不是必然开口）；被 TP 后能
  说出"刚刚被挪到某处附近"；无刺激时段零模型调用；静默期内冲动只入私记；
  刺激洪流场景（刷怪塔旁站立 10 分钟）下自主发言不超预算上限。

### TG-2 · 行动候选出口（= free-play F0 的事件源实现）

- 刺激 → free-play 候选生成：危险→撤离/反击评估；进度→重新规划；空闲→
  观察/散步。严格走 free-play §5.3（模型选择、宿主核对、运行权申请），
  不自起第二条 Flow。
- 验收沿用 free-play F0 标准：候选有来源，重复事件不重复决策，未知保持未知。

### TG-3 · Java 事件增补（2026-09-16 换引擎并收窄）

- **传送检测换引擎**：位置跳变复用 CD-L 的 16 格/1 秒模式，施加于她自身的
  `get_self` 采样流；判定条件 = 跳变发生且**当前无活跃控制会话、无反射在跑**
  （CD-0 §3.1 执行身份使"她没在动"成为可查询状态）。鞘翅着陆、爆炸击退、
  末影珍珠发生时必有会话或反射，天然排除误报。该判定做成 mod 侧事件，还是
  主进程用采样流组装，spec 阶段二选一。
- **仍待 Java 的缺口收窄为**：天气/雷暴变化、群系变化、日出日落标记、
  `player_damage` 攻击者实体（uuid/type/name，取 `source.getEntity()`——
  "谁射的我"现在只有 cause 字符串）。
- 全部纯观察，无游戏写操作。验收：真机 TP、天气切换、跨群系各出一条事件；
  攻击归属能指到具体实体与玩家名；鞘翅着陆与爆炸击退不产生 TP 记录。

### TG-4 · 空闲探索心跳与偶发闲聊

- 复用 long-goal 宿主唤醒（free-play §6.1），低频（分钟级起）触发一次
  "周围有什么值得做的"考虑；OV 线的 observe 分层是它的眼睛。
- 首批仅在无用户任务、无活动运行、配置允许时考虑；"休息"是合法选择且
  不占写锁。
- **偶发闲聊**是心跳的第二出口（纯发言，不产生任务）：间隔带随机抖动
  （空闲时 8–20 分钟一次机会，无固定周期）；内容必须引用真实来源——当下
  观察（OV 分层）、最近事件摘要或记忆（黄昏说夕阳、下雨想起上次淋雨），
  无来源的空洞寒暄禁止；用户最近有互动才开口，长期不在场时同一冲动降级为
  私记/日记（空房间自言自语与写日记是两回事，后者顺带喂 free-play 经历
  沉淀）；任何自主发言或用户回复后 10 分钟内抑制；计入同一发言预算
  （初值 ≤2 次/小时）。闲聊上下文用压缩摘要，遵守 CD §6"不把轨迹塞进
  模型对话"。
- 验收：无任何玩家消息的世界里，她能自行产生一次有依据的观察或短程散步，
  频次受预算钳制，用户停止后不被心跳自启；闲聊抽样全部能追溯到来源字段；
  用户离场时段零开口、日记条目增加。

## 证据与验收规则（2026-09-16 增补，对齐 CD §6）

- 每次冲动留痕：刺激记录 → 显著度与预算判定 → 模型决策（开口/私记/沉默）
  → 实际发言内容与来源字段，JSONL 落证据目录，主流程导出带版本与场景 ID。
- 失败样本必留：包括"该说话却沉默"与"不该说话却开口"，不只统计成功开口。
- 阈值（开口率、冷却、salience、预算上限）均为首轮工程建议，正式启用前由
  基线调整；成功率必须附分母与场景构成。
- 自动化不要求模型选中某个特定反应；固定场景核对条件与结果，多次运行观察
  分布（沿 free-play §11 口径）。

## 风险与开放问题

1. 发言节奏初值（预算上限、episode 窗口、习惯化衰减率、闲聊间隔分布）需
   真机调；全局开关（一键回到"只有玩家消息能唤醒"）与安静模式常驻。
2. 闲聊质量：无来源的空洞闲聊比沉默更伤人设——"闲聊必须引用真实观察或
   记忆"是硬规则，验收时抽样核对来源字段，违反即退回。
3. "被打残"阈值：初始 `healthBefore < 8` 或 `amount ≥ 4`，参数化。
4. TP 检测换引擎后仍有边界（激流贴地、活塞推动等无会话也无反射的位移），
   spec 阶段列全并定兜底策略。
5. 额度归属：对话冲动与行动候选建议共享 free-play §6.2 的"自主预算"池，
   避免两条出口各自无限花；发言预算是该池的子额度，spec 阶段定结构。
6. 用户在场判定信号（最近消息、应用活跃、MC 内玩家距离）取哪些、阈值
   多少，spec 阶段定。
7. **CD 验收依赖（2026-09-16）**：TG 复用的 CD-0/CD-L 模块均未验收；若验收
   期被纠正（寻路即在测试期多次修正），TG-0/TG-3 对应部分先同步再实施。
