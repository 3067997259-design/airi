### 5.7 聊天触发策略重构（X-10，主项）

用户确认，仿照 AstrBot 的触发模型。现有“白名单加提及”的门槛替换为三层策略：

| 发送者 | 规则 |
| --- | --- |
| 管理员（`admins`） | 所有消息都送达。消息首个字符为 `\` 时跳过。 |
| 黑名单（`blocked`） | 所有消息都跳过，也不进入上下文。 |
| 其他人 | 消息提及 AIRI 时送达。未提及时按 `mentionlessSampleRate` 概率送达。 |

- 送达的消息附带最近 `contextLines` 行聊天作为观察上下文。上下文排除黑名单与自身消息。
- 管理员的消息不要求回应。消息不是对她说的时，她保持沉默：不使用 `game_say`，不产生面向用户的回复。送达事实仍记 journal。
- 配置字段（`game-host.json` 的 `chatCommands`）：
  - `enabled: boolean`
  - `admins: string[]`
  - `blocked: string[]`
  - `mentionlessSampleRate: number`（0–1，默认建议 0.2）
  - `contextLines: number`（默认建议 5）
- `ownerNames` 与 `requireMention` 被上述字段替代，不保留兼容回退。
- 保留：事件游标去重、自身消息过滤、限频（1 条/2 秒）、世界绑定、不可信输入纪律、完成门只认 game-host 回执。
- 涉及文件：`chat-commands.ts`（纯函数）、`game-host/index.ts`（轮询与广播）、`shared/eventa/game-host.ts`（配置与载荷加 `context`）、`renderer/bridges/game-host-install.ts`（回合文本与沉默指令）、设置页。

通过条件：

- 管理员：普通消息送达；`\` 开头跳过；不相关消息可沉默，且没有回复。
- 黑名单：不送达、不入上下文。
- 其他人：提及送达；未提及按概率；采样消息带上下文。
- 配置读写与设置页正确；限频、去重与自身消息过滤保持。

已定项（用户确认 2026-09-13）：采样率默认 0.2，上下文默认 5 行；`\` 前缀按管理员生效；黑名单不进上下文。`chat-trigger-spec.md` 仍需定稿事件载荷、沉默回合与设置页字段的细节。

## 7. 共同纪律

- **规范先行**：每批先写规范文档，再写代码。
- **测试**：纯逻辑用 Vitest；游戏协议、菜单同步与物理动作用真机验收。测试纪律沿用[仓库 Vitest 规则](../../.agents/skills/enforce-rules-for-vitest/SKILL.md)。
- **证据**：PASS/FAIL/BLOCKED/NOT-RUN 加证明范围；跨版本结论按实际构建与场景分别记录。
- **回执**：缺材料、无目标、背包满与条件不满足都返回可解释结果；不伪造成功。
- **重试**：网络重试不重复投料、发射、交易或丢弃。
- **依赖**：先搜内部实现。若需新库，列候选交用户选择。
- **提交**：未经用户要求不创建 commit。

## 8. 风险与回退

- **服务端权限与反作弊**：按实际权限报告 `allowed`/`denied`，不做作弊类动作。
- **双客户端资源**：两个实例同机运行，聊天归属靠玩家名，不靠窗口。
- **实时控制边界**：main 轮询约 150–250ms，不能承担发射窗口。逐 tick 逻辑进客户端模组（缺口文档 §3.4）。
- **MCP 工具名或读数形状变化**：动态查找加类型化失败，不猜。
- **大范围批次**：按增量推进，任一批次可独立回退；`movement.planner` 与 `vehicle` 参数都是显式开关。

| # | 条目 | 现象与影响 | 建议落点 |
| --- | --- | --- | --- |

| 2 | 移动腿内不读新鲜快照 | 复测（2026-09-14）维度切换时 `move_to` 已正确收敛为 `cancelled / dimension_changed`（此前的 >60s 挂起发生在 `worldIdentity` 缺失的会话，先修 §9-1 的绑定缺失与 `stopActive` 原因保留）；长腿无读仍可能延迟收敛 | 视 §9-1 修复效果决定是否补腿内周期读取 |

## 10. 能力深化接续计划（2026-09-14）

按 [能力深化草稿](./capability-deepening-draft.md) 和本轮代码核对，后续接续 [能力深化总方案](./capability-deepening-plan.md)。本节调整深化工作的依赖顺序，保留 MC-4 与移动修复批的历史验收记录。

- 站位中心、快照冻结、开门记账、连续行走、失败记忆、鞘翅扫描和 R8/R9 修复已有代码。深化阶段不重复实施这些已落地的改动。
- “连续行走已接入”尚不等于具备碰撞约束的任意方向走廊。“直线切段已接入”尚不等于能够绕山的粗路线。两者继续按 [地面走廊设计](./movement-corridor-design.md) 完成。
- 先落 CD-0：命令所有权、维度与新鲜度、未知地形和轨迹证据。然后推进地面质量、目标定位和工具选择。鞘翅单程控制通过后，再接跟飞。
- [目标定位](./target-tracking-design.md) 与 [空中跟随](./air-follow-design.md) 共用目标观测契约。[鞘翅路线](./elytra-navigation-design.md) 拥有飞行控制，跟随只更新追踪目标。
- [工具与挖矿](./mining-tools-design.md)、[投射物瞄准](./projectile-aiming-design.md)、[载具旅行](./vehicle-travel-design.md) 分批交付，复用执行令牌、地形观测与结果证据。
- 本轮只交付设计与离线复现。行为中交谈、自动重连、长期目标与自由游玩实现不纳入本轮。MC-0a 版本测试继续暂缓。
- 选定实现方向以现有模块和游戏版本 API 为基础。本轮不新增依赖。若后续实现需要外部库，先按仓库要求列候选交用户选择。

## 11. 红石与生电首阶段（2026-09-15，范围已确定）

新增 [红石施工与局部维修设计](./redstone-automation-design.md)。首个目标是使用 Litematica 在给定平地居中布置投影，通过生存操作搭建甘蔗机，自主发现线路衰减并完成最小维修。

- 五层能力中的使用、复刻、局部适配、调试维护，先由这一有限场景覆盖。通过本案例不代表所有红石设施均受支持。
- 施工依赖 CD-0 的控制与观测契约，以及地面站位和精确放置。首阶段提供蓝图和材料，不等待完整工具升级、鞘翅或长期目标系统。
- 原始蓝图、施工进度、候选维修和已验收维修分别保存。功能验收通过的维修进入后续结构核对依据。
- 故障原因与参考修法只供验收侧使用。游戏代理通过独立任务上下文接收蓝图与目标，不读取本设计及相关讨论中的答案。
- 第五层自主研发保留为开放探索：提出一个小问题、做有限实验、记录结论与未解问题。复杂机器与原创设计不作为本阶段完成条件。
