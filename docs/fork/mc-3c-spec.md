# MC-3c 规范：鞘翅与炽足兽 + 服务器聊天下单端到端（Phase 3）

日期：2026-09-13。状态：规范定稿，实施未开始（用户显式开启条件批）。上游：[MC-3 立项评估](./mc-3-terrain-mobility.md) §3/Phase 3、[Minecraft 执行计划](./minecraft-execution-plan.md) MC-3c、[多信道设计](./multichannel-scenario-design.md) P3（后者的通用信道契约在后，本批只做 MC 侧最小确定性件）。依赖：Phase 1 ✓（foot movers）、Phase 2 ✓（船/马/矿车）、MC-0c/0d ✓（命令/回执/反射）、MC-1c ✓（技能与桥）；（可选）MC-2c/2d 不是前置。

通过条件（本批两段）：
1. **鞘翅/炽足兽**（原草案）：装备→起飞→巡航 ≥100 格→着陆误差 ≤4 格闭环；烟花/耐久耗尽与取消有界收敛；炽足兽完成熔岩面短程移动与上下。
2. **服务器聊天下单端到端（用户确认的最终场景形态）**：在**自建本地服务器**里，用户在聊天框（MC 聊天与 AIRI 聊天，二者都要）下达指令，她执行并如实回报；他人消息不执行；断线/取消有界收敛。语音信道不在本批（属多信道设计）。

## 服务器与两客户端环境（D0，吸收 MC-0a 遗留）

- **服务端**：自建本地 **Fabric 1.21.1** 服务器（offline-mode；localhost/LAN）；`fabric-api` + **mcpfabric 服务端入口**（`environment:"*"`，`main` entrypoint）；服务端能力组逐项验证（`message_player` 等需服务端的工具；`world.*` 服务端侧读取）。
- **客户端**：AIRI 客户端 = 现有夹具实例（NeoForge+Connector+mcpfabric 客户端桥；协议层兼容 Fabric 服务端，记录为环境事实，不新增第二套游戏环境）；**用户客户端 = 第二实例**（离线身份任意，用于区分聊天发送者）。
- **身份与归属**：两客户端不同玩家名；聊天指令的"所有者"按玩家名配置（默认仅所有者）。世界/连接代次沿用 MC-1b 绑定（`worldId` 回退 `connection-scoped`、`connectionId`）。
- **夹具搭建设备用服务端 OP/作弊**（发射塔、熔岩湖/诡异菌钓竿、烟花/鞘翅发放），验收动作本身不依赖作弊；搭建与发放记录在证据里。
- 这一步同时补 MC-0a 的 NOT-RUN：环境 B、服务端装桥能力组、1.21.11 移植冒烟与资源测量（可在此环境顺带跑）。

## D1 模式接入（鞘翅/炽足兽）

- `game_move_to.vehicle` 增 `'elytra'`（复用 MC-3b `VehicleMover` 分发，新增 `movement/elytra.ts`）与 `'strider'`（熔岩面）。
- 不与 foot 混用：`fallbackToFoot` 仅在未起飞前有意义（起飞后必须完成着陆）。

## D2 鞘翅控制状态机（增量 2）

1. **装备**：`getEquipment`/`getInventory` 找鞘翅 → `swapSlots` 换入胸甲槽；失败 → `unavailable`。
2. **起飞**：站高台边缘 → `jump` → 离地后 `useItem` 放烟花 → 抬头 30–45°。
3. **巡航**：目标高度带（默认 y_goal+30，按地形扫描抬高）；每 tick 调俯仰：低于带抬头、高于则俯冲；速度低于阈值/掉出发射 → 放烟花（间隔 ≥1s）。
4. **着陆**：距目标 ≤80 格进入进近——扫着陆点（半径 8，避水/熔岩/悬崖）→ 俯冲到位上方 → 拉平贴地；失败重试一次后 `stuck`。
5. **收尾**：返回位置与消耗统计（烟花数、耐久变化）。

## D3 避障与补给（增量 3）

- 前方扫描（`world.raycast`/区域切块复用），遇山抬高、遇峡谷绕行、水面保持离水高度。
- 补给：烟花计数低于阈值（默认 3）→ 提前着陆并报 `elytra_low_supply`；耐久低 → 换备用鞘翅，无备用按低耐久策略提前着陆。
- 安全网：低血/岩浆/水中 → 反射优先，抬头滑翔到最近可着陆点（有界）。

## D4 服务器聊天下令（MC 侧最小件，增量 1）

- **摄取**：game-host 轮询 `chat.getRecent`（游标、≤1 Hz、断线复位）。三层触发（用户确认 2026-09-13，仿 AstrBot）：
  - **管理员**（`admins`）：所有消息都送达；消息首个字符为 `\` 时跳过。
  - **黑名单**（`blocked`）：所有消息都跳过，也不进入上下文。
  - **其他人**：消息提及 `AIRI` 时送达；未提及时按 `mentionlessSampleRate`（默认 0.2）采样送达。
- 送达的消息附带最近 `contextLines`（默认 5）行聊天作为观察上下文；上下文排除黑名单与自身消息。按消息序号/cursor 去重；频率上限 1 条/2s；忽略自身 `send_chat` 回声。
- **归属与沉默**：管理员消息不要求回应；不是对她说的消息可以沉默：不执行动作、不使用 `game_say`，送达事实仍记 journal。v1 中 AIRI 聊天窗口允许出现一条简短说明（完全静默留给后续批次）。
- **契约**：eventa 事件 `gameHostChatCommand`（main → 渲染端 leader）在现有字段（`messageId`、`sender`、`senderUuid`、`text`、`receivedAt`、`world`）上增加 `trigger`（`admin` | `mention` | `mentionless-sample`）与 `context: Array<{ sender, text }>`；配置 `chatCommands: { enabled=false, admins=[], blocked=[], mentionlessSampleRate=0.2, contextLines=5 }`。`ownerNames` 与 `requireMention` 被替代，不保留兼容回退。字段命名对齐多信道候选契约（channel=`game-chat`），不新造记忆/任务系统。细节以 X-10 的 `chat-trigger-spec.md` 为准。
- **执行**：leader 收到事件 → 以该文本与上下文作为用户输入发起聊天回合（归属：channel=game-chat、世界绑定、原始消息引用入 journal），模型按现有 MC-0c/1a/1c 工具面执行；完成门只认 game-host 回执（不变）。
- **安全**：黑名单消息丢弃；送达的服务器聊天仍视为不可信输入（同 web 注入纪律），不改工具权限。默认关闭。
- **回报**：执行结果可通过 `game_say` 回聊天（她说"到了/没烟花了"），回答文本与回执证据分离（完成门规则不变）。

## D5 验收夹具（启动时搭）

| 夹具 | 用例 |

## 增量拆分（先服务器/聊天，后飞行）

1. **增量 1（去风险优先）**：D0 服务器 + 两客户端 + 服务端桥能力组；D4 聊天摄取与执行链路（新触发策略，先写 X-10 规范）；用**现有 foot 动作**（move/collect/say）做端到端验收（MC 聊天 + AIRI 聊天各一条；黑名单忽略；采样带上下文；`\` 跳过；取消/断线）。补跑 MC-0a 遗留冒烟与资源测量。
2. **增量 2**：D1/D2 鞘翅基础闭环（状态机 + 单测 + 发射塔真机）。
3. **增量 3**：D3 避障/补给/安全网 + 山脉航线/补给不足/水岛真机；炽足兽熔岩移动。
4. **增量 4（可选）**：下界顶棚高速航线（默认关闭）。

## 风险与回退

- 服务器反作弊/权限：服务端能力组按实际权限报告（`allowed`/`denied`），不假装成功；飞行遵守 vanilla 模型，不做作弊类瞬时飞行。
- 双客户端资源：两实例可同机运行；聊天归属靠玩家名而非窗口。
- 多信道未实施：MC 侧只做最小摄取/执行，通用语音与跨信道契约留给 `multichannel-scenario-design.md` P3；字段命名对其候选契约，避免二次迁移。
- 烟花/材料消耗：单程记录消耗；低补给强制着陆。
- 回退：`vehicle` 只是显式参数；聊天指令默认关闭；失败回 foot 或诚实失败。

## 明确不做

- 鞘翅花式（俯冲爆速、末影珍珠跳飞、船飞）、跨维度自动路线网、作弊式飞行。
- 通用多信道实现（语音输入/输出、视频、跨信道归属统一）——属多信道设计文档；本批只做 MC 聊天文本这一信道。
- 服务端插件/反作弊适配、白名单以外的多人协作指令。
